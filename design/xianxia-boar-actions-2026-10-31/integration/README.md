# 妖猪动作接入 · 2026-10-31

用户批准将移动、拱击、冲锋、狂暴、受击、死亡接入 Cocos 战斗。

- 初版 `pack.py` 从保留的256px独立原帧缩制128px运行帧（当前已升级，见末尾256px接入记录）；187帧、2048×1536，常态与暗红各一张RGBA图集。原图、视频、旧版图集不覆盖。
- `TowerMonsterArt` 按真实AI阶段播放拱击，按M06机制阶段播放冲锋；移动循环仅在位移时播放。受击使用生命变化；死亡由击杀账本确认，播放后保留末帧0.35秒。
- 2026-10-31用户补充：狂暴必须在发动完成后开始，持续期间维持变红和120%体型；到期或死亡立即恢复。M02新增独立模拟时间截止值，按现有加速施压强度采用15秒；维持每只怪仅触发一次。死亡播放常态版本。
- 狂暴期间的移动、拱击、冲锋、受击都使用暗红图集，缩放围绕统一脚底锚点。外观不改变碰撞、伤害或奖励。
- 定时器随快照保存；验证拒绝续时篡改，允许正常到期解除。当前开发期无需兼容缺少新字段的旧快照。

## 查看

`play.html` 使用实际编译的Cocos战斗渲染，提供六类动作对照和演武试打。对照模式是暂停战斗的合成动作场景；“实战试打”恢复真实战斗逻辑。左侧常态、右侧狂暴；狂暴选项完整展示发动、15秒保持和结束，死亡选项展示退出狂暴后倒地。

## Boss体型调整

用户认为体验中的Boss过小，批准至少放大2倍。本次将妖猪Boss基础画布从最高110调整到220，普通妖猪不变；狂暴在此基础上叠加1.2倍。死亡解除狂暴但保留Boss基础尺寸。视野裁剪余量随大体型调整，脚底锚点和物理碰撞保持原规则。`boss-size-tests.log`记录29项相关测试结果；`boss-size-browser.json`记录两种横屏下尺寸和状态文字位置的复查。

## 256px原帧接入（当前版本）

用户批准修复Boss放大后的模糊。`pack256.py`生成`boar-v3`常态／狂暴图集，每帧256×256，图集4096×3072；不经过缩图或AI重绘。`TowerMonsterArt`现加载v3；v2的128px图集与原打包脚本均在原路径保留。

`verify256.py`逐像素核对全部187×2帧，包含透明通道，结果为374帧零差异（`hd-pixels.json`）。`hd-comparison.png`在相同264px显示尺寸比较原128px和新256px帧。`hd-tests.log`记录29项通过；`hd-build.log`记录编译；`verify-hd.cjs`核对实际GPU帧尺寸、六类动作、两种横屏及演武运行，结果写入`hd-browser.json`。

资源代价：两张RGBA图集展开共96 MiB（原128px版本24 MiB），仅在妖猪动画被请求时加载；旧v2不会同时加载。本次验证为桌面浏览器，未作为微信真机内存验收。当前改动恢复原帧细节，并不补造原视频中不存在的细节。
