## 接入内容

青白实体剑沿各自的半径、相位、速度、高度运行，部分反向，剑尖顺着飞行方向，保留0.24秒短尾。范围沿用批准预演的25%扩大量。腰部点取角色动作图集的(140,201)，随角色朝向、动作倾斜和御剑浮动变化；不改变角色地面坐标。前后遮挡按未压缩的世界纵深排序。

`WuwoMotion.js`同时给出完整世界半径的剑身扫碰端点和透视后的显示端点，避免把横向椭圆的屏幕高度误作战斗范围。近身剑意与飞剑共用逐敌0.6秒冷却、6目标上限，伤害预算不变。仅实际正伤害事件在目标身上显示0.18秒短斩痕。基础环剑诀保留原来的圆周径向飞行。

剑境流纹复用批准 V2 的两仪来源，裁出四段低透明流纹。剑体复用原批准资源。本轮模型调用0、费用0 CU、云端上传0；历史生成费用不重复计算，未知来源ID不编造。V1否决稿、V2批准预演、全部旧原片和索引保持封存。

## 验证与边界

- 107项专项测试全部通过：四方向远端覆盖、腰部锚点、两阶剑数、共享冷却、确定性存读档、基础环剑、资源释放和失败回退。
- 全量测试由2037项/1827通过/210失败变为2045项/1835通过/210失败；按失败名称比对，无新增失败。详见[全量对照](verification/test-comparison.json)。
- TypeScript前后虚拟源码对照均为42项诊断，无新增；项目类型检查不是全绿。详见[类型对照](verification/typecheck-comparison.json)。
- Cocos web-mobile构建成功；1280×720两阶、移动、暂停重建、御剑腰部抬升、降阶、死亡、退出、真实404素材回退、844×390小横屏检查通过。训练前后普通存档和localStorage未改变。
- 三段MP4均完整解码通过。原生浏览器记录见[主验收](qa/attempt-03/browser.json)与[小横屏](qa/attempt-04/browser.json)。
- 独立审查发现的“屏幕透视压缩了世界命中范围”已修复，并以四方向180距离回归覆盖。

本轮未发布微信版本，未做实体手机帧率和发热测试。当前接入完成；后续技能继续从素材库复用，并分别审核。

## 并行开发边界

录像和全量检查完成后，另一个开发任务修改了 `TowerRun.js`、`TowerView.ts`，接入妖兽机制并修正部分类型标注。本任务保留了这些并行修改，之后再次运行107项专项全部通过（`verification/concurrent-check.log`）。本包的构建、录像、全量/类型对照对应 `source/verified-checkpoint` 中按原验收SHA256精确保全的源码；`source/runtime-final`亦保存此接入检查点，不代表把并行妖兽机制的新改动一并做过完整构建验收。当前工作区没有被回退。
