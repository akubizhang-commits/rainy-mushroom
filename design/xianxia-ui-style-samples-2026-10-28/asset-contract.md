## 4. 样片交付与视觉检验

以下为四件 A 小样下载后的技术检验合同；本稿尚未执行图像检验，也没有产出通过/失败截图。2×2 原图是待验样片，不自动等于四张可接入的透明图标。

| 项目 | 候选合同 |
|---|---|
| 源图 | 每张最终交付 **512×512 RGBA PNG**。模型若原生输出更大，保留原始图，另导出此源图；不将低清图放大充当合格源图。 |
| 运行时派生 | **128×128 RGBA PNG**，由批准的源图缩小；各尺寸保持同一画布、中心锚点与构图。正式目录及加载方式由主线程定。 |
| 小图检验 | 对每张候选看 **48×48、32×32 实际尺寸**，同时看 128 大小。不能只看 512 图或放大的缩略图。32/48 是视觉检验尺寸，不自动改变当前节点/触控尺寸。 |
| Alpha | 画布外部 alpha＝0；边缘抗锯齿可半透明，实体核心应有实色。黑白棋盘不是透明。检验深浅底是否出现白边、黑边、矩形底、空洞或宽透明光晕。 |
| 留白与安全边 | 512 图四边至少 **48px 空白**，对应 128 图至少 12px、32 图至少 3px；剑尖、瓶盖、剑气和高光均不得出界。主体最长边建议 360–400px，按视觉重量校齐，不把药瓶压成与剑一样宽。 |
| 中心与细节 | 视觉重心靠近 `(256,256)`，不因自动裁透明边而漂移。身份所需细线在 32 图至少约 1.5px、关键间隙约 2px；达不到则简化纹样，不能靠加大光晕补救。 |
| 圆形容器 | 现 `TowerMenu.skillIcon` 为 96×96 圆形节点。四角不得承载唯一识别点；需另看圆形容器中的剑尖/剑柄是否被裁，不预设资产一定会被圆形裁切。 |
| 背景对照 | 四种物品都在共同浅底 `#F2F0E6`、深底 `#102A26`、透明棋盘上检验，并确认与已选 A UI 协调。验画底板单独排版，不能写入 PNG。 |
| UI 分工 | **图标不画文字、数字、冷却遮罩、倒计时、技能等级、品质外框、选中框、锁头、加减按钮或“已装备”徽记。** 这些由 UI 实时叠加。同一 ID 不因锁定/选中/升级重复生成资产。 |

主线程下载本次 2×2 原图后，先逐格确认四种物品身份、有效分辨率、是否串图/裁边和实际 alpha，再整理成统一缩放、统一底板的 A 小样验画板。不得只凭拼图整体好看便判定四格可用，也不得将不足 512 的单格放大冒充合格源图。标签如“落云宗 / A / 灵石 / 32px”由排版层加，不能成为图标内容。

检验问题：

1. 隐去名称和颜色时，32/48 图能否分别读成晶石、珠核、药瓶、飞剑？
2. 同一风格四种物品是否共享边缘处理、光照方向和细节密度，而不是每张来自不同游戏？
3. 灵石和妖丹是否明显不同？药瓶是否会被误认为新增塔内可拾取消耗品？
4. 四件 A 小样是否适合宣纸玉青 UI？是否有某件靠更大尺寸、更亮光晕抢眼，破坏全组一致性？
5. 深底、浅底与圆形容器中是否都完整、清楚、不出现 alpha 污边？

验画记录字段：`UI 方向：A 宣纸玉青（已确认）`、`四件图标逐件通过/需改/待验`、`保留点`、`需改物品/原因`、`下一轮允许范围`。**当前四件图标均待验，批量制作未获批准；不展开附录清单。**
