# 藏经阁 UI/UX 评审包

2026-10-30，v0.2。产品方向已经确认；用户指出 v0.1 两张视觉稿与现有游戏不符，旧视觉不采用。当前版本校准风格、布局与交互，尚未接入正式游戏。

先打开 `style-reference.html` 查看项目已有主峰、丹霞院落和背包界面。新静态图按 `art-prompts.md` 制作，配套原画在 `references/`，可直接上传给制图模型。

## 直接体验

打开 `index.html` 即可，不需要安装依赖。图片已随包保存，断网也可浏览。手机请使用横屏。

原型包含：

- 馆内四个入口：丹药录、兵器谱、百器鉴、功法修习。
- 典籍目录、名称/类别搜索、戒指/防具章节、搜索无结果。
- 双页阅读、前后翻条目、品质范围切换、页内上下滚动。
- 每册独立的阅读位置记忆、逐层返回、减少动效。
- 鼠标点击、触屏轻扫、Tab/Enter与左右方向键、Escape。

“重置体验”只清除本原型的阅读记忆，便于重复评审首次选书流程。原型使用独立浏览器偏好键 `luoyun-library-ui-review-v1`，不读取或修改角色、货币、技能、背包或任何正式游戏存档。

原型暂借**已有主峰原画**作界面色彩对照，画面固定标注“非藏经阁内景”。四个入口仅用编号和框线定位，不再绘制虚假的立体书架。展开书页仍是布局容器，中缝、纸边和页厚需正式原画补齐；不能把本轮截图当作最终书本美术。浅灰青底、墨绿无衬线文字和按钮样式与现有游戏对齐。

物品插画复用了现有已验收资源。丹药展示当前两种条目；兵器和装备只展示代表样本，正式版需接入全部当前开放定义。属性范围样本取自当前配置，本原型不会随之后的平衡改动自动同步。

“主峰”和“功法修习”仅演示去向与返回关系，没有实现主峰或技能系统。未实现手柄或真实设备性能验证。

## 本轮优先评审

1. 四个入口的位置、大小是否合适？书架氛围待新内景原画评审。
2. 两页各放一类信息的阅读方式是否舒适？
3. 844×390时，页内上下滚动是否可以接受？
4. 目录、搜索、翻页和合卷的返回关系是否符合直觉？

产品功能开发与正式美术接入，在这轮布局确认后进行。

## 文件

- `interaction-spec.md`：UI布局、交互、边界与验收要求。
- `style-reference.html`：已有美术与UI对照板。
- `references/`：可直接上传给制图模型的原画，以及现有界面截图。
- `art-prompts.md`：静态图片清单及每张图完整提示词。
- `prompts/`：逐张独立的纯文本提示词。
- `art-manifest.json`：文件名、尺寸、背景与锚点清单。
- `screenshots/`：1280×720和844×390的入口定位、丹药、装备、目录与空态截图；不代表已制作内景。
- `verification.json`：浏览器交互与尺寸检查结果。
- `archive/v1-rejected/`：保留两张不采用的旧视觉稿，不作为出图参考。

## 验证边界

检查在隔离的桌面浏览器上下文中按两种横屏视口运行，覆盖选书、翻页、首尾、阅读记忆、搜索、返回、品质切换与功法入口返回。检查页面脚本错误、图片加载、可交互区域尺寸和视口溢出。截图不等于真机触感或设备帧率验收；真机适配仍是正式开发阶段的工作。
