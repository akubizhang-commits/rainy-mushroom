# 两份PRD策划评审报告

> 文档状态（2026-09-21）：历史设计/记录。不作为本轮新增地图或角色/奖励规则来源。 当前基线见[设计文档索引](../design/design-document-index.md)。

日期：2026-09-21。评审对象：[游戏设计PRD v1.0](archive/game-design-prd-v1.0.md)、[关卡设计PRD v1.0](archive/level-design-prd-v1.0.md)。

## 结论

**方向评审通过；可以继续L01灰盒样板；暂不通过整批十关直接进入正式制作的规格评审。**

两份文档已经明确昆虫尺度、统一旅人、自然交互、失败恢复和十关学习顺序。但还存在2项P1和4项P2问题。主要差距是跨段状态、返回路线、关键数值和资产外形尚未形成可直接执行的规格。

本报告中的P1/P2是评审问题严重度，不是原PRD的功能排期标签：P1＝应在相关功能或关卡实现前解决；P2＝可在代表样板中补齐，但正式验收前需要关闭。没有证据支持把这些问题列为已经发生的线上P0故障。

本轮保留两份v1.0正文，仅新增评审记录和更新交接；修改建议尚未写入规则或游戏。此前的ID、引用、链接核对只证明文档结构完整，不等于本轮的策划评审通过。

## 1. 问题清单（按严重程度）

### R01 · P1 · “重置本段”缺少跨段物体和依赖状态的处理规则

**位置：** 游戏PRD第172行；关卡PRD第64–79行、第167行、第269行、第303–312行。

文档要求自由推动物体，同时要求只重置当前段落的对象，并且不能把下一段对象拉回当前区域。只列重置对象ID不够决定以下情况：

1. 玩家把B段的小石推到C段，并让它压在C段承重叶上。
2. 玩家回B，选择重置B。
3. 小石按出生段归属应回B，按当前区域归属又应留C；若回B，还会改变C段叶片和其上玩家／其他物体的支撑。

第10关另有“只重置所选分流区域”，但没有定义玩家中途换路、把石头推向汇合点之后，何为当前所选区域。不同实现会造成撤掉其他路线支撑、生成重叠物、旧支撑引用残留，或者名义重置后仍然无解。

**建议修订：** 增加统一的状态恢复表，而非只补一句“不能死锁”。至少确定：

- 每件关键物的稳定ID、不可变出生段归属、当前空间位置；出生归属不随移动自动变化。
- 普通死亡、手动重置本段、整关重开、跨检查点分别影响人物、物体、支撑关系、桥计时、叶片位移、甲虫位置／朝向、风相位、蒲公英剩余时间中的哪些字段。
- 重置对象被另一段使用时，采用什么依赖处理；建议从清除支撑关系、把人物放到验证安全点、恢复对象、重算接触的一次原子操作开始，而非逐帧搬回。
- 分流关用明确段落ID或检查点恢复范围，不依赖“玩家看起来选择了哪条路”。

**关闭证据：** 一张事件×状态字段表；跨段推石后重置、石压叶后重置、分流换路后重置三个用例，每个都能说明对象最终位置、角色安全性和剩余主解。不要用禁止所有跨段移动的隐形墙解决。

**负责角色：** 系统策划＋玩法程序；测试确认恢复用例。

### R02 · P1 · 第5关“桥后返回观察”的无配重路线没有闭合

**位置：** 关卡PRD第165–171行；游戏PRD第183行。

第5关计划让玩家过桥后离开，观察空桥恢复，再通过配重理解“返回不用重新压茎”。但柔茎的施力点位于根部近岸，空置5秒后恢复。如果玩家已经在远岸，文档没有说明如何返回根部再次施力。

当前文字“可回到近岸的观察分路”有两种解释：若分路仍依赖该桥，恢复后回程不可确认；若本就存在另一条安全回岸路，应该画出来，并明确配重节省的是哪段路程，否则石头的收益也不清楚。这里不能直接宣判目标关卡无解，因为几何尚未制作；能确认的是无配重回程缺少可验证的完整路线。

**建议修订：** 采用“远岸可沿稍长的低根回路回到近岸，压石保桥能省去绕行”的结构；或者删除跨岸折返，改为玩家始终站在根部一侧完成配重观察。两者选一个写入区域图，不额外发明远程压桥按钮。

**关闭证据：** 在区域图上标出柔茎根部、远岸等待点、无配重回程、配重回程和检查点。分别验证过桥后等待超过5秒再回头、压石后等待超过5秒再回头；两种情况都不用自杀或菜单重置才能回去。当前给主线保留直走选项，不等于已经验证了这条可选回路。

**负责角色：** 关卡策划；玩法程序核对施力范围。

### R03 · P2 · 第6关有两种解题顺序，但未给出决定可解性的载荷与高度约束

**位置：** 游戏PRD第187行、第194–200行；关卡PRD第181–187行。

文档正确提醒角色也有重量，但“载人平衡高度可跳范围”仍交给制作时猜。所需的角色质量、小石质量、叶片刚度／最大下沉和出口高度没有组成一张关卡可达约束表。

用现有代码参数做静态核算：角色质量1、小石0.7、叶片最大下降52、容量2；忽略地面限位与瞬态，叶片下降量如下。

| 状态 | 下降量（当前逻辑单位） |
|---|---:|
| 空载 | 0 |
| 只有小石 | 18.2 |
| 只有角色 | 26 |
| 角色和小石 | 44.2 |

角色已在叶上再推走石头，会从44.2回升到26；先在外侧卸石，再跳上叶，则最终下降到26，并非持续保持空载高度。角色单独站上去甚至比原来仅有小石时更低7.8。两条顺序可以被设计成可解，但不能依据同一张“卸石后叶片升高”的静态图直接摆出口。

**建议修订：** 为PLT-05补四载荷状态的稳态高度、恢复速度与地面限位；为L06补入口根阶高度、推石可接触位置、推落接物区、载人叶面到出口的水平／垂直范围。设置“未卸石是否可达”和“卸石后两种顺序是否都可达”的明确判断，不要求编造最终坐标。

**关闭证据：** 两条顺序的真实控制器回放，覆盖稳态与回升途中起跳；记录实际载荷和落点。以上数值来自当前配置核算，不是目标版L06试玩结果，也不是不可解证明。

**负责角色：** 系统策划＋关卡策划。

### R04 · P2 · 关键植物的资产台账仍不足以约束外形，可能重复出现“违和素材”

**位置：** 游戏PRD第107–111行、第209–217行、第234–238行。

台账已有数量、用途、比例和验收流程，但“柔茎2种冠叶轮廓”“完整承重植物1套”没有定义两者的具体区别。美术仍需自行决定主茎数量、叶片着生方式、叶形、根部结构、弯曲范围；如果只按“有叶柄、能受力”制作，依然可能做出用户此前否定的杆顶贴叶、同弧度植物或独立叶桥。

问题不是缺现实物种学名，也不是必须先画完全部素材。缺的是能把设计规则落实为轮廓的代表资产简报。

**建议修订：** 先补PLT-02、PLT-05、ENV-01三张代表简报。每张包含：形态构成、与邻类区别、正常／受力／恢复状态的侧视小图、根部与地表接触、人物比例、哪些部位可抓或承重、禁止的造型。明确现有造型哪些已被用户接受、哪些仍是待替换原型。

**关闭证据：** 每类一个被确认的轮廓样板；同一场景并排摆放柔茎和承重叶，玩家无需白线或长说明即可区分横向推弯与向下承重。之后才批量扩变体。

**负责角色：** 美术方向＋系统策划。

### R05 · P2 · 发布平台与屏幕适配范围没有锁定，真机验收缺少明确对象

**位置：** 游戏PRD第34行、第254–256行、第281行；关卡PRD第58–60行。

“手机为主、浏览器试玩、Android和iOS各一台”没有区分微信小游戏、独立移动应用或移动浏览器；也没有明确横竖屏是否同为首批发布承诺。当前仓库既有Web预览，也有微信构建入口，不能从目录或现有构建能力推断产品已经决定全部渠道。

这会影响输入、前后台恢复、本地存档、画面安全区以及远处落点能否同屏看见。“低档Android”也不是可重复的测试条件。

**建议修订：** 新增平台支持矩阵：主发布容器、开发试玩容器、首批支持方向、窗口尺寸范围、是否允许旋转、具体基准设备／系统、关键用例。设备未提供时写为发布门槛待填项，不伪造机型或宣称验收。若同时承诺横竖屏，01／03／07分别交付攀爬、风跃、漂流的两种构图验证。

**关闭证据：** 明确首批发布目标和排除项；选定测试设备后，同一构建能重复完成输入、暂停恢复、关级存档与落点可见性检查。

**负责角色：** 产品负责人＋平台程序＋UI／测试。

### R06 · P2 · “静止2秒”不足以覆盖周期危险和检查点长期安全

**位置：** 关卡PRD第62行、第244–248行、第321行；游戏PRD第264行。

检查点要求安全，但统一测试仅静止2秒。甲虫可能在更晚才走到该处，桥在5秒后才恢复，风周期为8秒。错误摆在回弹范围或巡逻后半程的出生点，可能通过两秒检查，随后仍死亡。第9关“巡逻边界外”是正确设计意图，但需要比两秒更强的证据验证边界实现。

**建议修订：** 保留2秒作为快速启动检查，另加按危险周期计算的静置测试：甲虫至少覆盖完整往返＋转向停顿；桥覆盖空置倒计时和恢复；风覆盖完整周期及不利初相位。测试时间由配置或路程／速度导出，不再换成另一个统一固定秒数。

**关闭证据：** 各危险相位下复活，人物无输入仍安全；手动重置后也重复此项。不能靠给出生点短暂无敌把错误位置隐藏起来。

**负责角色：** QA＋关卡策划。

## 2. 应保留的设计与制作取舍

三项有明确文档依据的优点：

1. **KEEP：** 游戏PRD第31–45行、87–111行把昆虫尺度、植物支撑、不能用白线和微缩树明确写成约束，能防止重复走回旧美术方向。
2. **KEEP：** 关卡PRD第70–77行与各关失败矩阵明确区分普通落地和危险失败，且允许替代解法；这与用户希望自由探索的方向一致。
3. **KEEP：** 两份文档都区分当前实现、未来制作目标和实际验收；保留稳定关卡ID、先做代表样板，避免把自动通关当作内容和审美完成。

额外取舍：

| 决定 | 内容 | 原因 |
|---|---|---|
| CHANGE | 先补R01、R02，再排需要配重／回程／分段重置的关卡 | 否则规则和地图会互相返工 |
| TEST | 用L06验证载荷两顺序；用L07验证登乘、流失和恢复 | 这两类动态支撑比固定地形更依赖状态合同 |
| TEST | L01在触控、无口头解释下能否看懂攀附和高出口 | 它是后续九关的学习入口 |
| CUT（本阶段） | 用增加物种、道具、重复关卡来补目标时长 | 先做有效决策；不以内容数量掩盖路线缺口 |
| KEEP | 蜗牛只提供可选趣味，不强制等待；第10关不新增规则 | 有助于缓冲节奏和检验已学技能 |

## 3. 分项门槛

下表评价的是文档对下一阶段的准备程度，不是对未制作关卡给出游戏运行结论。

| 维度 | 结论 | 理由 |
|---|---|---|
| 产品幻想、核心原则 | PASS | 角色、尺度、玩法取舍一致且明确 |
| 核心循环与十关学习顺序 | WARN | 顺序合理；趣味、时长和理解仍未实测 |
| 通用状态与恢复合同 | FAIL | R01未关闭，跨段自由交互缺统一语义 |
| L01灰盒准备 | PASS | 可在现有动作规则下验证高出口与安全跌落回路 |
| 十关整批生产准备 | FAIL | R02回程未闭合，动态关卡参数仍需样板证明 |
| 美术量产准备 | WARN | 台账齐，但关键植物需可执行轮廓简报 |
| 手机发布与验收准备 | UNVERIFIED | 主容器、方向与设备基线尚未明确 |
| 新玩家测试方法 | WARN | 已避免把小样本当市场数据，但尚无试玩记录 |

生产成本主要风险：大量资产标P0，但代表轮廓未确定，过早制作变体会放大返工；同时横竖屏与多个发布容器若全部默认支持，会增加布局和回归组合。先确认代表素材、平台矩阵与恢复语义，再估工作量。

教学风险：L01一次包含走、跳、抓、爬、跳离和高出口；文字上已分区，仍需确认提示按真实行为触发，不能因为玩家绕过某个露根动作就漏掉下一条帮助。此项列为样板测试问题，尚无证据认定设计必然失败。

## 4. 建议的修订顺序与完成标准

1. **规格修订：** 先提交v1.1的状态恢复表和L05回程图，关闭两项P1。
2. **代表样板：** L01操作与轮廓、L06载荷、L07移动支撑分别验证；同时填写平台矩阵并补三类关键资产简报。
3. **验收补充：** 危险全周期静置测试，记录实际位置、相位、配置和结果；短检查继续保留，但不当作完整安全证明。
4. **生产推进：** 样板通过后再扩展十关。每项评审意见需记录“已采纳并验证／有理由不采纳／延期影响与范围”，不能只把状态全部改为完成。

本轮不建议增加新的玩法系统。最小证明仍是一个L01完整灰盒；完成它不代表R01、R02自动关闭。可以并行完善文档规则，但不应据此直接铺满十关美术。
