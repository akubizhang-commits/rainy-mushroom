## 1. 需要修改的发现

### R-01 · P1：角色局部受光既是验收项，又是高档可选

**位置：** 规范第275、279、320、509、522行；7.2、7.6、13.1、13.2。

正文要求亮斑按身体覆盖区域变化，12秒脚本要求帽顶依次受光，LIGHT-01引用该脚本，首个样板还要求角色受光；但7.6把“局部角色受光”放入高档候选。基础／标准档是否可以用整身缓慢明暗变化，是否仍能通过首轮验收，没有唯一答案。

**后果：** 技术美术可能交付合格的基础档，视觉却按逐部位受光判退；也可能为了满足一个未定档的效果，提前增加角色分层和材质工作。当前`MicroForestSpriteArt.ts`第150–151行使用整节点镜像和整张Sprite颜色控制，不构成局部受光已经接入的证据。

**建议修订：** 明确首轮默认验收档位。建议基础档保留世界锚定日斑、稳定接触影及角色跨光域的柔和整体明暗；标准档再试局部接收蒙版。“帽顶→肩手”的效果单独列为增强项，或明确它必须进入标准档并分配实现工作，不能两处同时含糊。给LIGHT-01按档位写预期，验收录像标注档位。补充角色底色、固有体积阴影、环境受光、隐藏／受伤颜色的叠加顺序，避免靠覆盖`Sprite.color`互相抵消。

**关闭证据：** 同一12秒路径的基础／标准对照；左右朝向、背面攀爬及隐藏状态下身份色不变，低档不丢提示。这里需要确定验收边界，不要求现在实现复杂光照。

### R-02 · P2：遮挡人物的实体根壳不能使用装饰前景视差

**位置：** 规范第79–80行，LAY-03／LAY-04。

实体根壳前沿和近草共用“1.0–1.08”的候选镜头系数，但前沿必须与根缝本体、碰撞及藏身位置重合。按表选择1.08时，镜头移动100逻辑单位，前沿与1.0的根体会产生8单位相对漂移；相对文档H=44的人物碰撞高度，这已不是可以忽略的偏差。

**后果：** 角色可能被看似错开的洞口边遮住，根壳与根体分离，或视觉上离开庇护仍像藏着。问题是表格允许了错误配置，不是已确认当前游戏存在该偏移。

**建议修订：** LAY-04拆成实体前沿与装饰近景两个子类：前者严格1.0，继承所属对象／zone变换，只改变绘制前后顺序；后者才允许1.0–1.08，且不得充当洞口边、承重面或危险轮廓。

**关闭证据：** 藏身、出来、横向移动镜头、纵向攀升、横竖屏切换时，前沿与根体接缝保持重合，危险头部和实际洞口不被装饰草遮住。

### R-03 · P2：唯一交互目标有展示要求，缺少完整的选择与保持规则

**位置：** 规范第353–358行；对照游戏PRD第207行。

规范要求手掌“指向唯一目标”，并扩展到进洞、治疗、休息等情境。PRD已有“攀附优先松手、藏身优先出来”以及距离／面向选择和旧对象优先序建议，不能说完全没有优先级；缺口在于新动作如何加入，以及提示、按下和持续操作是否使用同一目标。

**后果：** 靠近根缝和可推石时，画面提示“藏身”而按键开始推石；接近休息点与可抓柄时目标来回闪动。后续只改图标并不能消除这种分歧。

**建议修订：** 在PRD输入规则基础上补一张完整冲突表，覆盖推物、柔茎、抓柄、根缝、洞道、治疗芽和R。先过滤不成立动作，再选择目标；提示与输入消费同一个目标ID。按下后持续推／压期间保持该对象，松手或目标失效再重新选择；明确候选切换的距离／面向边界，避免细微移动导致图标跳变。不新增专用按钮。

**关闭证据：** 三组重叠场景：石＋根缝、洞道＋抓柄、休息点＋治疗芽；分别覆盖空手、推物中、满血／缺血。显示目标与实际动作一致，失效后不执行上一个目标。

### R-04 · P2：“松手立即恢复”没有区分人物姿态和植物状态

**位置：** 规范第354行；对照同文第188行。

“推石／压茎”共用一行，取消栏写“松手立即恢复”。如果恢复的是人物手臂，这合理；如果是柔茎，则与“空置5秒后约0.8秒恢复、载荷保持、遇阻等待”相冲突。同一栏不能要求接入者猜主语。

**后果：** 可能把动作结束直接连到植物复位，重新出现玩家站在桥上却回弹的旧问题；也可能误把停止推石理解为把石头还原。

**建议修订：** 拆成推石、压茎两行。松手立即结束推姿和持续受力声音；石头留在物理解算位置；柔茎按载荷／空置计时器恢复，仍承重不恢复、遇阻等待。植物恢复音绑定实际回弹事件，不能绑定松手。

**关闭证据：** 松手留石；桥上松手继续承重；离桥空置5秒后回弹；计时中重新承重；回弹受阻。动作、形变和声音分别检查。

### R-05 · P2：生物危险预兆的音频分组与抢占规则未落到具体事件

**位置：** 规范第418、444–448行。

SND-07把生物足声、翼振、预告和攻击放在同一素材包；混音另有“关键反馈”和“生物”两个并发上限。文档明确危险优先，这是正确方向，但没有规定同一生物包的预兆走哪个组、满额时替换谁。只按素材包自动归组的实现仍可能把预兆当普通生物声裁掉。

**后果：** 蚂蚁队列、甲虫和蜻蜓同时出现时，关键预兆可能在并发限制中丢失；加载失败之外，又多出一种难追查的“有动作没声音”。这不等于静音不能玩，但破坏了已承诺的声音反馈一致性。

**建议修订：** 给每个声音子事件补`cueId / bus / priority / instanceKey / maxInstances / stopEvent`。危险预兆与伤害进入关键反馈，日常步足／翼振进入生物组；明确关键组满额时的替换顺序及同事件去重。暂停／回区时循环按当前状态恢复，一次性事件按是否已消费处理，不因重绘再次播放。

**关闭证据：** 人为压满普通／生物音源后触发一次预兆，仍能听到且不重复；两个危险同时预告时有明确保留策略。用事件日志与录音验证，不能只检查音效文件存在。

### R-06 · P3：光照分类标题与实际数量不一致

**位置：** 规范第248行标题“五种光”，下表实际列出LGT-01…08。

建议改成“八类光照配方”或不含数量的“光照职责与分层”；保留LGT-08两个子预设的说明。关闭证据为标题／ID核对，不需要游戏测试。

## 2. 审美与可用性：待样板判断，不列为已证实缺陷

本次实际查看了1280×1280光照示意PNG。它能解释六种空间的光源与遮挡关系，文字未见裁切，但明确属于结构示意，不足以确认最终美术好看。

- **斑驳光：** 示意板01的亮斑更接近平面色块。正式样板应验证不规则叶隙、软硬边和苔土纹理共存，避免变成地面黄色花纹；不能仅增加空气束代替表面受光。
- **树内／地下：** 03与04已能看出侧孔和顶井区别，但壁面、台阶、土层目前仍是简化块面。后续用纵向木纤维与土层／细根区分空间，不能直接量产这版几何外形。
- **角色：** 板中站立帧只是比例参照。头手比例、背包左右归属、帽内脸和推物姿态仍需实际尺寸动作接触表，不能由这张板认定已经优化通过。
- **小屏UI：** 文档有触区、字号和尺寸矩阵，缺少可供目视确认的布局稿。样板应补竖／横屏的行走、攀爬、滑翔剩余时间、暂停长文四种构图，再验收同时按压与安全区。此处是下一份设计证据，不把尚未执行真机测试本身算作文档错误。
- **声音：** 尚无交付音频，不能判断循环自然、音色悦耳或手机外放可辨。先做推石／桥回弹／风预兆三种完整声音闭环，再定整套混音。

## 3. 已可保留的设计决定

1. 昆虫尺度、统一C旅人和自然支撑关系明确，用户曾否定的微缩树、白线、悬浮叶板等没有被重新引入。
2. 动作覆盖攀爬背面、手部接触、推物受阻、轻伤／救回／耗尽，承重与危险部位比“全部物体一个碰撞框”更清楚。
3. 光束、表面日斑、接触影分开，前后景不全屏泛白；光线不改变可走性。
4. 六类本批生物与十九类候选分开，示意／候选值／实际完成状态有说明，没有要求立即量产整个生物库。
5. 静音可玩、颜色之外的提示、HP整合现有HUD和绒毛时间依附动作按钮，适合继续保持。

以上是文档方向认可，不是素材成品验收。
