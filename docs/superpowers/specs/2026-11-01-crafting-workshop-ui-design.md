# 丹房与器坊：配方工坊流程与界面设计

日期：2026-11-01。状态：设计提案与可点击交互稿，尚未接入正式游戏。

用户确认：参考提供的两张制作界面的交互和布局，重做左侧导航；保留本项目宣纸、青玉风格。用户已否定并移除炼丹、炼器小游戏，本方案不恢复控火、节拍、塑形、拼图或工艺评分。

交互稿：`design/crafting-workshop-2026-11-01/index.html`。独立演示，不写游戏存档；配方和图标来自现有项目，钱包、库存、境界提示是模拟数据。截图只作结构参考，不提取或复用其中美术。

## 1. 设计目标

玩家可以在同一屏完成“挑选成品 → 看懂效果与材料缺口 → 调整数量 → 制作”，不必在长段配方文字和底部按钮之间来回滚动。

以选配方和管理资源作为制作行为。成就反馈来自清晰的成品展示、材料到账和获得结果；制作不增加额外操作门槛或强制等待。原炼丹、炼器、购买、掉落、境界、背包和经济规则保持。

| 截图结构 | 本项目采用方式 |
|---|---|
| 左侧层级分类 | 丹房／器坊两项一级切换，下面只显示当前用途分类 |
| 中间密集图标网格 | 每格保留名称、可制作状态和明确选中角标 |
| 右侧大成品和材料 | 成品、核心药效／属性、材料图标及持有／需要数量 |
| 固定底部费用与制作 | 数量、总费用、阻塞原因、唯一提交按钮组成同一区域 |
| 点击材料进一步操作 | 查看来源、前往楼层详情，返回恢复配方上下文 |

不采用截图中的副本体系导航、多层折叠菜单、兑换材料替换、装备继承、巨大持续金光，以及无关聊天／邮件入口。

## 2. 入口与左侧导航

原丹霞峰／炼器峰院落入口保留。入殿打开铺满可用横屏空间的工坊，不再在院落上叠一层窄配方窗口。

左侧固定导航采用两层结构：

- 一级：丹房、器坊。当前项为青玉实底＋明确文字，点击另一项切换制作领域，同时更新当前院落上下文。
- 丹房用途：全部、疗伤、修为、突破。
- 器坊用途：全部、武器、法衣、戒指。

两个一级入口始终可见；只有当前领域显示四项用途。用途不再嵌套境界、购买方式或来源副本。当前项加侧边标记，不能仅靠颜色识别。

“炼制／购买”是当前图录上方的交易方式切换。“境界／品阶”和“品质”是图录筛选。背包放右上角；返回院落放左上角，不挤占分类位置。

默认从哪个院落进入，就选中哪个领域。第一次进入选择“全部”，丹房优先可炼的疗伤丹；器坊使用已开放的最低适用品阶和下品。后续保留每个领域的交易方式、分类、筛选、配方、滚动位置。主动换配方、品质或交易方式将数量设为1；单纯返回背包／来源不重置数量。

## 3. 横屏布局

布局由顶部资源栏、左导航、中配方网格、右配方详情组成。正文区域独立滚动，右侧制作区固定，整页不滚动。

| 区域 | 1280×720参考布局 | 844×390紧凑布局 |
|---|---|---|
| 安全边距 | 左右16起，叠加宿主安全区 | 使用真实安全区，避免刘海和手势区 |
| 顶栏 | 约62高，返回／标题／货币／背包 | 48高，缩短标题与辅助标签 |
| 左栏 | 148宽，按钮至少48高 | 约112宽，用途可独立滚动 |
| 配方栏 | 约460宽，4列 | 约245—310宽，3列 |
| 详情栏 | 剩余宽度，约580 | 至少340，正文可滚动 |
| 右底操作区 | 约146高 | 约138高，始终显示数量、费用、按钮 |

实际使用可用宽度分配，而非把整张1280画布缩小。若安全区后不足三栏最小宽度，左栏改为48高的“领域／分类”弹出选择器；配方网格降为2列，详情不少于320宽。仅支持横屏，竖屏显示旋转提示。

紧凑高度下缩小成品装饰环并收起背景文案。允许详情滚动，不缩小触摸热区。高阶配方材料可能超过一行，材料区域常规3—4列，窄屏2—3列多行，费用和提交按钮仍不滚动。选中后正文回顶，切换数量不改变正文滚动位置。

## 4. 图录与筛选

丹房以现有13张丹方为数据源。器坊以当前141条品质配方为数据源；品质筛选只显示当前一个品质，同一装备不在网格中重复三次。

丹房筛选：全部境界／炼气／筑基／金丹，以及“仅可炼制”。疗伤丹无专属境界，适用当前境界筛选时保留；突破丹按目标境界筛选，卡片标出服用条件，不能因其 `realm` 为空而被错误移除。器坊筛选：全部品阶／凡器／法器／宝器／灵器；下品／中品／上品；“仅可炼制”。未开放品阶不提供可点击空筛选。

网格中的卡片包含：

1. 原物品图标，完整主体、等比缩放。
2. 成品名称，最多两行；长名可点详情完整显示。
3. 当前单件状态：“可炼制／可购买”“缺材料”“贡献不足”“境界未达”“背包已满”等。使用文字，不只变灰。
4. 选中边框和✓角标；品质、品阶用小文本区分，不套用星级。

图录可制作状态按**单件**计算，不受右侧批量数量影响。修为丹需库存确认但资源充足时仍列入可炼，标记“需确认库存”。状态来自现有报价和规则校验，UI不另写一套成功率或成本公式。

默认排序稳定：配置顺序；不因一次制作后资源变化突然重排。仅可制作筛选开启时，当前项制作后不再符合条件，可暂留选中项并显示“资源已不足”；玩家主动更换筛选后再消失。空结果给出“清除筛选”按钮。

## 5. 右侧详情

成品展示区保留成品名称、图标、品质／类型、当前持有、本次产出。低分辨率图标最大展示不超过其可读范围，不用巨大模糊图代替说明。

### 炼丹

核心信息先于配方故事：疗伤效果；修为丹适用境界、增加修为、本境剩余服用额度；突破丹前置条件和**服用突破成功率**。制作本身确定成功，不把服用成功率写成炼制成功率。完整描述通过“详情”展开。

修为丹另显示“本境剩余X颗，同境丹药共用额度；当前同境库存Y颗”。库存超过剩余额度时允许沿用原确认机制；换数量、配方或资源状态后旧确认失效。

### 炼器

显示部位、品阶、品质、佩戴境界及所有固定属性；武器展示基础攻击与词条，法衣／戒指展示对应属性。长词条进入正文滚动区。对比当前装备作为可展开信息，不占据首屏主要位置；首版可暂不做对比，但不能编造提升百分比。

不添加材料替换、品质随机、词条重抽或属性继承。

### 材料

每种材料是可点击卡片，显示图标、名称、“持有／本次需要”、足够或缺X。需求始终乘当前数量；点击数量后材料、产出、费用、主按钮同步更新。

点击材料打开来源面板：持有、本次需要、缺口、已有来源文字与楼层列表。点击楼层先去楼层详情，不自动开战、不扣材料。关闭面板或从来源返回时恢复领域、分类、配方、数量、两个滚动位置。来源无可进入楼层时显示解锁条件，不放空按钮。

购买模式仅展示购买费用、相同成品说明；材料卡区域隐藏，不展示灰色材料诱导玩家认为买成品也要材料。器坊购买列表仅包含 `shopAndCraft`。

## 6. 数量与提交

右底固定为两行：数量控制；总费用＋主按钮。下方一行保留阻塞原因或成功状态。炼丹范围1—99，炼器1—10，沿用现有上限。

数量支持减、数字输入、加、最大可做。数字输入在移动端使用数字键盘或数字面板，确认后裁剪到合法整数。长按不触发制作，滑动网格不选中。

“最大”取材料、贡献、灵石、库存／装备容量和单次上限的最小可执行数量。境界等硬门槛不满足时为0并禁用；不把数量自动改成0。修为丹的服用额度不能当成可制作上限：原规则允许确认超额库存，应计算含确认的最大可做，再在提交时提醒。

材料不足时按钮禁用并标明具体缺口，来源入口仍可点。只读、塔战中、容量满、货币不足分别给出明确原因。出现多个原因时详情保留所有材料缺口，底部按只读／塔战／境界与额度／容量／材料／货币的顺序显示首要原因。

常规一次点击制作；只有现有修为丹超额库存等业务规则需要确认。确认面板包含本次数量、将持有的同境丹总数、本境剩余额度及总费用，提供“调整数量”和“仍然制作”。购买同样执行原额度规则。

点击后锁定提交请求的模式、配方、数量和请求标识；显示“保存中”。成功保存才显示制作成功并更新货币、库存、材料。失败不扣费不发物品，保留同一请求重试；连点、退后台和重载不能重复制作。具体事务仍调用 `craftPill/buyPill/craftGear/buyGear`。

## 7. 获得结果与返回

成功后在右侧展示一段180—250ms的轻量出现反馈：丹药淡墨晕与青玉亮边，装备轮廓亮边与小幅落定。反馈是保存成功的表现，不人为添加炼制计时器。

结果可用轻量面板显示“获得X×N，已放入背包”，按钮“继续炼制／查看背包”。继续后保留当前配方和数量，并重新报价；不自动再次提交。背包只查看，不自动服用、穿戴或替换装备。频繁批量制作时可采用不阻挡网格的右侧结果条，具体演出样式交由实现阶段试验。

关闭只影响页面，不清除已经成功制作的物品。保存进行中禁用再次提交和配方切换，退出请求待保存结果返回后执行。保存失败恢复可编辑状态，已有存档乐观并发检查继续生效。

## 8. 视觉与素材

用户选定宣纸、青玉。建议底色 `#F4F0E4`、纸卡 `#FFFDF5`、墨字 `#29463F`、青玉主色 `#35695C`、分割线 `#C7CEBD`、少量旧金 `#A08046`、缺口文字 `#994C3B`。标题用清晰宋体，正文用现有中文无衬线。

界面强调清楚的列分区和成品，而非密集按钮描边。分类、选中卡、唯一主按钮共用青玉语义；材质装饰留在边缘。无持续粒子、旋转光圈或闪烁可制作标签。

现有丹药、装备、材料图标直接复用。128px物品主体125px的既定规则继续有效，UI不扩大格子掩盖图标比例。按钮、边框、选中态、材料连线、纸底使用程序绘制，无需先付费生成。

已发现部分高阶装备和六种炼器材料尚缺对应静态图；交互稿用带名称的文字占位明确区分，不假称已拥有素材，也不拿参考游戏图补齐。素材补齐独立于流程验收，需要时另给用户制图提示词；未调用Scenario或Meowa付费服务。历史丹炉／器胚提示词不适用于本方案。

## 9. 可访问性与实现约束

主要触摸目标至少48×48，间距至少6；小横屏正文目标16px、辅助文字不低于14px，不能整体缩放到不可读。三栏内分别控制滚动和裁剪，装饰不拦截输入。提供显著键盘焦点；Tab按导航→筛选→图录→详情→提交，Enter不绕过确认，Esc优先关闭顶层面板。

本项目首版面向触摸与鼠标，键盘基础操作可用；不凭设计稿宣称已支持完整手柄。正式实现继续使用已有Cocos宿主和安全区；单独工坊视图可从TowerMenu拆出，避免新增大量重复菜单代码。复用图片缓存，列表大量项按可见区复用节点，禁止每帧重建图录。字体、纹理尺寸、实际Cocos触摸误差需真机验证。

## 10. 交互稿边界与验收

交互稿演示领域／分类、炼制／购买、品阶品质筛选、图标选择、材料来源面板、数量与费用联动、缺料、模拟制作、模拟背包。其数据是导出的当前配方，钱包及库存只存在页面内存。它不是正式存档、经济规则、境界／服用额度、失败事务或移动宿主实现。

验收清单：

- 1280×720和844×390中主按钮、当前数量、费用不被滚动内容覆盖。
- 两个领域的分类与成品明显不同，切换后返回可找到原配方。
- 材料“需要”与制作数量一致，图录状态明确是单件可做。
- 买成品时不再显示材料成本；只炼不可买的配方不进入购买列表。
- 查看材料来源能回来继续，不自动开塔战。
- 缺料、货币不足、容量满、境界未达、额度耗尽、超额确认、只读、保存失败、重试逐项验证。
- 原经济回归、幂等与失败原子性测试通过；此次UI重设计无须升级存档或重置用户进度。
- 实际手机检查点击热区、中文清晰度、输入键盘、安全区和长列表帧时间；浏览器截图不代替真机验收。

设计决策由本稿提出、待用户体验确认：共用工坊框架可在丹房与器坊之间直接切换；左栏用途分类；购买在图录顶部切换；最大可做；轻量结果面板。用户已确认的视觉取向与截图参考范围不需重复确认。

## 11. 最终确认：修为丹仅限同境服用（2026-11-01）

用户撤回跨境药效提案，确认保持正式游戏现有逻辑：修为丹仅限所属大境界服用，越阶和降阶均禁止，不引入半效或其他跨境折算。

| 角色境界 | 可服用的修为丹 |
|---|---|
| 炼气 | 培元丹（50）、凝气丹（90） |
| 筑基 | 合气丹（100）、养元丹（180） |
| 金丹 | 真元丹（160）、紫府丹（280） |

每境6颗，同境两种修为丹共用额度；旧境剩余额度不结转。买／炼限制仍为仅本境，瓶颈、封顶、溢出确认规则沿用现有设计。跨境服用拒绝，不扣丹药或额度。

交互稿保留“预览境界”用于检查界面：同境显示实际修为，高阶显示“不可越阶服用”，低阶显示“不可降阶服用”。跨境时不以“当前0修为”暗示可以消耗丹药。正式代码已符合境界限制，本次不修改玩法代码或存档。
