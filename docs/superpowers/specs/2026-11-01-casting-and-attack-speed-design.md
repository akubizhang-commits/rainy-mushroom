# 可移动施法、动作互斥与双速度词条方案

日期：2026-11-01。状态：用户已授权开发；核心实现、构建与行为验收完成，整体数值平衡仍待专项调优。

## 1. 已确认目标与本轮边界

用户已确认：施法期间允许移动；同一时间角色只能释放一个技能或进行一次普攻。已释放的飞剑、剑阵等效果可继续独立运行。用户同步装备设计加入施法速度与攻击速度。

用户随后明确要求“按照建议方案进行开发”。本文的动作时长、排队和目标锁定规则已接入运行代码；不生成美术，不调整装备词条表或单招伤害。实现与验证记录见 `reports/casting-actions-2026-11-01/README.md`。

目标是使出招可读、调度公平、两个速度词条各有用途，同时保持横屏自动战斗中的移动自主权。不增加手动技能栏，不用强制站桩制造施法代价。

## 3. 单一角色动作状态

统一状态：空闲 → 起手 → 出招（可能多段）→ 收招 → 空闲。

- 起手到收招完成，全程独占角色动作槽；普攻也使用同一槽。
- 位移输入持续有效，施法不额外减速；敌方现有减速/定身按原规则影响移动，不额外取消动作。
- 普通受击不打断、不重置前摇。当前不新增眩晕、沉默或可被打断机制。
- 不允许技能取消普攻，也不允许普攻取消技能；不提前排入第二个已启动动作。
- 同一模拟步最多启动一个新动作；旧动作到点结束后可在该步启动一个新动作，不附加全局冷却。
- 自动战斗不会为了释放技能强制走向目标。
- 死亡立即取消未发出的段数和待发动作，停止本局后续伤害结算；已生成视觉可收尾，但不能在死亡结算后继续杀怪或领奖。

占用的是“角色正在出招”，不是“伤害仍然存在”：

| 类型 | 占用动作到何时 | 之后仍可独立运行 |
|---|---|---|
| 普攻 | 攻击动作结束 | 已触发的合法后续效果 |
| 剑气斩、长虹连发 | 最后一发发出并收招结束 | 已发出弹体 |
| 剑影分光 | 放印并收招结束 | 留印延迟与交错斩击 |
| 两仪、四象 | 布阵并收招结束 | 阵法持续、逐跳伤害 |
| 周天 | 启阵并收招结束 | 环剑持续与碰撞 |
| 御剑 | 一次发剑动作及收招结束 | 本批飞剑飞行 |
| 万剑归宗 | 召出剑雨并收招结束 | 后续剑雨各段 |
| 无我剑境 | 每次新战斗首次启动动作结束 | 常驻剑境，无需逐跳重新施法 |

御剑蓄剑生成继续按现有间隔独立计时，生成剑不等于发剑；发剑需获得动作槽，一批剑视为一次技能动作，不按剑数占用多个动作。无我首次启动参与同一公平队列且不要求附近有敌人，启动后本战斗不再重复排队；暂停恢复不重复启动。

御剑特殊边界：用新0.20秒起手替代原弹体0.32秒聚剑准备阶段，不把两者叠加；出手事件之后才进入原有飞行阶段。起手记录本批可用剑数上限，出手时按剩余有效目标与在途预留伤害分配，实际发出多少才扣多少；期间新生成的剑留到下一次动作。无有效目标时本批不扣剑、动作正常收招，不凭空射向替代目标。已有飞剑追踪与悬停位置语义继续保持，不强行套用直线技能的锁向规则。

## 4. 第一轮建议时长

以下为零施法速度时的基准秒数，单招伤害和既有冷却先保持。所有新增数字是试调值。

| 技能 | 起手/施法 | 角色连续出招 | 收招 | 独立效果说明 |
|---|---:|---|---:|---|
| 御剑术 | 0.20 | 一次发出本批飞剑 | 0.08 | 蓄剑间隔、飞行速度不变 |
| 剑气斩 | 0.18 | 高等级三发，基础间隔0.16 | 0.06 | 发出后弹体独立 |
| 纵横剑气 | 0.30 | 单发 | 0.08 | 两条刃面仍为一招 |
| 周天剑阵 | 0.18 | 单次启阵 | 0.06 | 原持续时间与命中间隔不变 |
| 长虹贯日 | 0.35 | 按等级1/2/3发，基础间隔0.16 | 0.08 | 角色最后一发后可收招 |
| 剑影分光 | 0.15 | 单次放印 | 0.05 | 留印0.65秒、斩击间隔按现有形态表0.08秒 |
| 两仪剑阵 | 0.35 | 单次布阵 | 0.08 | 布阵后0.5秒首跳，原5秒持续 |
| 万剑归宗 | 0.35 | 单次召出剑雨 | 0.10 | 召出后0.2秒首击，其后间隔0.15秒 |
| 无我剑境 | 0.20 | 仅首次启动 | 0.05 | 常驻命中窗口不变 |
| 天地一剑 | 0.45 | 单发 | 0.10 | 不新增长时间引导 |
| 四象剑阵 | 0.45 | 单次布阵 | 0.10 | 布阵后0.5秒首跳，原6秒持续 |

阵法的持续计时从实际布成开始；万剑的0.2秒是召出后的独立延迟，不与0.35秒起手混为一项。新规则会推迟这些技能首次伤害，需要专门验收。

## 5. 攻击速度、施法速度、冷却缩减

三个属性保持不同职责；同类来源加算后应用，不把百分数点数直接当小数。

| 属性 | 缩短 | 不缩短 |
|---|---|---|
| 施法速度 C | 技能起手、角色主动连发间隔、技能收招 | 技能CD、御剑产剑间隔、飞行、剑影留印/独立斩击、阵法持续/跳频、剑雨后续落剑、常驻命中窗口、普攻 |
| 攻击速度 A | 普攻起手、出手、收招组成的整套动作及普攻起手周期 | 主动技能、持续伤害、技能CD、装备特效内部CD |
| 冷却缩减 R | 现有代码中由冷却接口管理的时间 | 角色动作速度、DOT跳频、弹速 |

公式：

- 技能可加速动作段：`实际段时长 = 基础段时长 / (1+C)`。
- 普攻周期：`1秒/(1+A)`；普攻动作：`0.2秒/(1+A)`，继续保持出手在动作中点的当前比例。
- 技能冷却：`基础CD×(1−R)`，装备R继续合并封顶30%。御剑产剑等目前已使用冷却接口的特例保持，不借此方案偷偷改成施法速度。
- +50%施法速度使0.45秒起手变0.30秒，不是0.225秒；+100%速度代表两倍速度、时间减半。

技能在实际起手时开始CD；等待出手时不扣资源、不消耗蓄剑、不抽取武器攻击随机数、不启动CD。普攻同样从实际起手计下次可用时间。CD到期只表示“可候选”，不表示自动获得动作槽。

上述CD规则只适用于实际具有周期冷却的释放路径。普通御剑当前每批释放不重新写入1秒技能CD，而由产剑、动作槽和已有特殊封锁共同控制；保留此例外，不因为配置里有 `cooldown:1` 就给每批补上1秒CD。万剑结束对普通御剑设置的既有等待仍保留。无我常驻也不新增周期CD。

单技能极限起手间隔至少是 `max(实际CD, 自身动作总长)`；多技能混用还要加排队影响。因此施法速度不是技能DPS的直接乘数，也不能用攻速百分比保证整套输出同比增长。

起手时快照有效速度、攻击属性、技能等级、时间表；动作中不变速。每个正动作段至少占一个60Hz模拟步，按累计时间转换到不早于理论时刻的步号，必要时使后续段至少晚一步；逻辑、动画和校验统一使用同一时间表，避免各处重复取整。零长度的“单次出手”事件不另收一帧动作税。

本提案不另设未获确认的速度百分比上限；上线只接受装备正式表的合法值，拒绝NaN、负值和非法词条。测试0、20%、50%、100%及装备实际最高值，100%可用合成测试，不代表新增100%装备。

装备侧约定：对战斗层输出汇总小数 `castSpeed`、`attackSpeed`、`cooldownReduction`。当前攻速来源为武器，施法接口读取防具；未来有其他合法部位时用汇总函数，不能让多部位同类词条静默失效。具体品阶、部位、词条数值和替换掉的装备预算由装备设计表决定；该表未完成前不宣称装备收益已验证，不擅自追加免费词条。

## 6. 公平调度与目标判定

不继续让技能数组的固定遍历顺序决定永久优先级。每个模拟步（包括角色忙碌时）维护候选资格和等待年龄；只有动作空闲时才选择并启动。每步先推进移动与已到时的战斗事件、清理失效目标，再维护候选，最后至多启动一个动作：

1. 技能CD到期、目标/距离/视线/资源/自身特殊规则满足时，记录首次“可释放”的模拟步。
2. 技能连续保持可释放时保留等待年龄；失去资格就退出候选并清除年龄，下次重新取得资格重新排队。不对无目标时间积攒爆发优先权。
3. 技能候选按等待最久优先；同一步就绪按固定内容顺序打破平手，并保存该顺序版本，不依赖对象遍历。每技能只保留一次就绪机会，不积累补发次数。
4. 普攻存在合法目标且已就绪时，最多允许一个技能先出手；然后下一次动作空闲必须给仍然合法的普攻。已经等待中的多个技能继续保留年龄。
5. 普攻失去目标时立即解除其保留机会，远程技能不会为了无效普攻空等。候选选定后、起手前再次校验；失败者退出，尝试下一个，不锁住系统。
6. 持续伤害、追踪弹体和常驻伤害不参加这条队列，它们没有新角色动作。需要重新布阵/发剑/启阵的事件参加。

御剑与万剑仍保留已有互斥：剑雨不能与普通御剑重叠抢占同一剑群；等待既有御剑弹体结束，剑雨期间不新发普通御剑。万剑无资格时不预占角色动作槽；是否保留其到期后阻止新发御剑的现有剑群预约，保持现状，并通过测试确认不会阻止其他技能/普攻。后续若改动这项能力专属规则，单独评估，不冒充纯施法调整。

目标规则建议：

- 起手前必须有符合现有几何和视线要求的目标；周天/无我等自中心技能保持其自身无需敌人的资格规则。
- 定向技能起手阶段跟随当前有效目标调整朝向，最后三分之一前摇锁定方向（天地零加速时恰为最后0.15秒），施法加速同比缩短锁定窗口；锁定后不瞬间转向。
- 地点技能同样在最后三分之一前摇锁定落点，布成后不追踪。锁定前目标死亡可按现有目标选择规则重新选取；锁定后目标死亡或离开，仍朝锁定方向/地点完成，允许落空。
- 若锁定前目标丢失且无替代，保留最后有效方向/落点完成本次动作，不退款、不重开CD，避免无目标反复起手；角色继续移动。
- 定向弹体从实际出手时角色位置发出，连发共享锁定方向，每发起点随角色位置；地点技能保持锁定世界坐标；普攻沿用起手锁向、出手重新判定距离的现有规则。
- 锁向只影响上身出招朝向，不改变玩家移动输入方向。

## 7. 表现与提示

角色要有起手、释放、收招三段可识别表现，特效与伤害时刻使用同一时间表。施法速度改变动作动画播放速度；已经发出的独立特效保持原速。

长起手技能可显示轻量施法进度和技能名，短动作无需大读条。技能界面显示“基础/当前施法时间、动作总时长、冷却”；排队只提示“等待出手”，不能显示成额外冷却。人物面板区分攻速、施法速度、冷却缩减，并解释“持续伤害频率不受施法速度影响”。

长虹等连发还需展示连发段数；剑阵持续、剑影延迟不计入角色施法时间。装备对比不要把“施法+20%”标成“伤害+20%”。

横屏844×390、1280×720分别检查：移动+施法、怪物预警、血条与进度提示不互相遮挡。优先复用现有素材；需要静态图时提供prompt让用户制作，动态素材如需付费另按现有授权和素材留存规则执行。

## 8. 影响与主要风险

| 方面 | 预期影响/风险 | 必须核查 |
|---|---|---|
| 总输出 | 动作变长会挤占其他技能/普攻；不能只看单招CD | 每招实际次数、伤害、等待时间和总DPS |
| 普攻构筑 | 攻速缩短周期和占用，但频繁保底普攻也会让技能等待 | 近身/远程站位下普攻占比与技能等待 |
| 施法构筑 | 施法速度增加空闲动作时间，拥挤时价值更高 | 少技能与全技能两端，不能只测满配 |
| 冷却装备 | 多技能全就绪时，继续减CD可能主要增加排队 | CD就绪率与真正出手率；CDR+施法速度组合 |
| 技能投资 | 新学技能可能抢动作，降低旧构筑总收益 | 学习前后对照；退点/继承/进化组合 |
| 技能职责 | 多段主动连发受施法加速，独立持续伤害不受 | 爆发型与阵法型收益差异，不强行保证等值 |
| 命中/手感 | 移动施法、锁向与首击延迟改变落空率 | 移动Boss、快速小怪、绕柱、贴身与撤退 |
| 装备触发 | 普攻变多可能增加触发、吸血；技能节奏影响第N次施法 | 原有内部CD、每招计数、重复命中账本不改变 |
| 生存/关卡 | 首波启动更慢；杀敌/回血节奏和危险暴露改变 | 首次入场、新层、精英/Boss、失败率、HP |
| 自动施法 | 固定顺序可能饿死后排技能，失效候选可能卡住 | 公平性、无目标、目标死亡/无敌/视线丢失 |
| 存档 | 新增排队年龄、动作阶段、快照时刻 | 暂停/恢复不重发、不跳前摇、不刷新CD |
| 性能 | 高速度使单位时间事件变多；同时存在的旧特效不会因串行消失 | 高密度、最高合法速度、低端设备 |
| 多端 | Web与Cocos时序及动画映射需一致 | 共享逻辑、资源引用、回放一致性 |

不自动用增伤补偿所有损失。先测实际频率与命中，再决定调整基准动作时间、装备预算或怪物难度。调度拥堵优先查调度与动作占用，不先提高全技能伤害。

## 9. 状态、存档和结算约束

新增统一动作快照至少表达：actionId、类型/技能、起手步、各段出手步、结束步、目标/锁向、锁定状态、速度和攻击快照、已发段索引。调度保存候选首次合资格时间及普攻保留机会；加载后重新检查当前资格，不能按墙钟补发。

战斗暂停冻结模拟时间、动作、候选等待、CD、弹体和持续伤害。保存/恢复保留阶段与命中账本，读档不重新抽随机攻击，不重触发起手装备效果。

跨层遵循本项目“新尝试CD归零但保留自身起手”的已有规则：新战斗丢弃旧动作/弹体/队列，重新起手；暂离恢复原战斗则完整恢复。具体入口必须区分新建与恢复，不能统一重置。

按当前用户授权可重置本模式旧版本不兼容存档，但不得删除其他模式/游戏/账户数据。正常新版本存读档、失败原子性和重复领奖验证必须保留；应更新版本与严格校验，不靠放宽任意字段通过存档。

## 10. 验证与实施顺序

先冻结实施时的代码及正式装备表版本，保存对照基线；本工作区存在并行装备改动，本文读取仅代表写作时观察，不是全局冻结版本。

1. 为动作时序建立单一纯计算接口，标注每段是否受施法速度影响，接上已有速度/冷却接口。
2. 合并角色动作入口和公平调度；先测试0速度、维持伤害和冷却，再接新时长。
3. 接入动画/提示与装备面板，映射正式词条产出；同步存档与Cocos共享模块。
4. 用相同版本、相同配点/装备、相同随机种子与移动策略比较前后，先做孤立机制探针，再做真实关卡。未经测量不联动改伤害。

必须通过的行为测试：

- 任意模拟步最多一个角色动作，动作中仍可位移；短CD不会自我重叠或结束后补发。
- 20%、50%、100%施法速度的起手/连发/收招按公式变化，普攻与独立效果时序不变；攻速只改变普攻对应时间。
- 30%CDR与两种速度组合正确，等待不提前启动CD/消耗资源；负值/NaN拒绝。
- 连发所有段仍属一次施法，装备每招计数只记一次；阵法每跳不重新申请动作。
- 持续合格的技能按年龄出手，不能被新就绪技能反复超越；普攻仍合法时最多被一个技能越过；失效候选不会占槽。
- 目标死亡、离开射程、绕柱、无敌、锁向后穿身、撤退时连发，不追踪造成必中或从旧角色位置出招。
- 起手、连发中、收招中、排队中分别暂停/存读档；结果与不暂停对照一致；死亡/过层不重复出手或结算奖励。

数值采样：基础角色、普攻为主、少量主动、多主动、阵法为主、进化组合；0速度、正式装备低/中/最高速度、两种速度叠加、CDR上限。覆盖近/远站位、静止目标与移动目标、密集怪群及代表楼层精英/Boss。性能另用最高合法负载。

每项至少记录：理论/实际起手周期、每技能出手次数和DPS、普攻次数和DPS、空闲/各动作占用、技能等待P50/P95/最大值、落空率、清场/击杀时间、剩余HP和失败率。技能等待统计只包含连续合格时间。

初步回归告警线（助手建议，不是既有平衡目标）：对照总输出或击杀时间变化超过10%、失败率绝对变化超过5个百分点、原本常用技能出手次数下降超过20%，必须逐项解释；不以全部落在线内替代实战验收。代表Boss每构筑至少30组配对种子作探索采样，失败也计入，样本不足时不宣称概率结论。

验收分开给出：规则正确、表现清楚、数值可接受。前两项通过不代表第三项通过；正式上限装备未定时，装备全量平衡为 NOT ASSESSED。

## 11. 需要确认的提案项

用户核心方向已经确认；本轮建议新增的决策为：采用上表动作时长、施法速度作用于角色连发与收招、等待最久技能优先且普攻最多被越过一次、最后三分之一前摇锁向、普通受击不打断。具体装备词条数值等待装备设计表，不在本方案中替用户重定。
