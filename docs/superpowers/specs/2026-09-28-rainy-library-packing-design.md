# 雨后森林图书馆 · 塞书整理原型设计

日期：2026-09-28 · 状态：设计已逐段确认，待审阅书面稿
前作：`2026-09-28-rainy-library-design.md`（灰盒 5 关已完成，用户试玩结论：整理本身无聊——每本书只有一个标好的格子，没有决策）

## 1. 目标与边界

**一句话**：暴雨把书冲了一地，在水涨满之前，根据书脊线索把书分进两个书柜，并把每一层塞得严丝合缝。

**用户已确定**
- 整理类方向保留；核心乐趣改为"塞得刚刚好"（尺寸装填）+"看线索归类"（多属性拼合）。
- 压力改为按步数涨水，不再随时间上涨。
- 布局采用"两柜多层"：线索决定进哪个柜，尺寸决定进哪一层。
- 先做 3 关核心；用户自己先玩，觉得"想玩下一局"后再找 5 人试玩。
- 差异化约束沿用前作：不使用 Librarian 的名称、美术、文案、分区名、"3072"、三技能组合。

**不在本次范围**：正式美术、音效、漏水点、晾书架、书堆叠压、放大镜、知识型线索、金币、真实广告、旧代码清理。

## 2. 规则

### 2.1 书柜
- 屏幕上方左右各一个柜，每柜 2–3 层。
- 每层有 `height`（`short`/`tall`）和 `length`（4–7 单位）。
- 过关：所有层都**正好塞满**（层内书厚度之和 = 层长）。

### 2.2 书
- `thickness` ∈ {1,2,3}，`height` ∈ {`short`,`tall`}。
- 高书只能进高层；矮书任何层都能进。
- 一层剩余空间小于书厚度时放不进。
- 层内的书自动左对齐靠紧；抽出一本后，其余的书向左靠紧。

### 2.3 线索
- 每个柜有两个标志：一个颜色（`color`），一个花纹（`pattern`）。例如左柜"红 + 菌伞纹"，右柜"红 + 叶脉纹"。
- 一本书属于某柜，当且仅当它的颜色和花纹都与该柜相同。
- 书脊默认只露出部分属性（`shown` ⊆ {color, pattern}，且至少露出一个）。只露出两柜共有属性的书，就是模棱两可的书。
- 点书一下 = 翻开封面，完整属性全部显示；每本只需翻一次。

### 2.4 步数与水位
- 每关有步数上限 `steps`。以下操作各消耗步数：

| 操作 | 消耗 |
|---|---|
| 放书进正确的柜 | 1 步 |
| 从柜里抽书回地面 | 1 步 |
| 翻开封面 | 1 步 |
| 放错柜 | 2 步；书弹回，并自动翻开 |
| 放进正确的柜，但尺寸不合（太高、太厚） | 0 步，直接弹回 |

- 水位 = 已用步数 / `steps`，以画面上的水线表示。
- 某层第一次被正好塞满时，退还 `refund` 步（每层只触发一次；抽出后重新塞满不再退）。
- 已用步数 ≥ `steps` 且还没过关：进入复活等待。看（假）广告后退还 30% 的步数，每关一次；已复活后再次用尽即失败。

### 2.5 关卡

| 关 | 每柜层数 | 书数 | 新内容 |
|---|---|---|---|
| 1 | 2 层（全部是矮层） | 约 8 | 两柜标志完全不同，没有模棱两可的书；步数宽松，只教"塞满" |
| 2 | 3 层（有高层） | 约 12 | 加入高书；两柜同色，开始出现模棱两可的书 |
| 3 | 3 层 | 约 15 | 模棱两可的书更多，步数更紧 |

- 生成器：先把每层长度切成若干厚度为 1–3 的书，并按层高分配书的高度（高层可以含矮书），再分配线索、打乱位置。由此保证一定有解。
- 最少步数 = 书数。初始 `steps` = ⌈书数 × 1.5⌉，由机器人测试调参（见 §5）。

## 3. 画面与手感

- 顶栏：暂停、关卡名、剩余步数。中上部约 50% 是两个书柜，柜门上方挂标志，每层用淡色小格显示剩余空位。中下部约 35% 是地面，书平铺、互不遮挡：书宽度表示厚度，高书画得更高。水从底部上涨。
- 拿书：放大、跟手，同一时刻只认一根手指（记录 touch id）。
- 拖到某层上方时预览：放得下显示绿色虚影；放不下显示红色，并标出原因（太高、太厚）。
- 放入：书滑进去靠紧，给出"咔"的反馈。一层正好塞满：整层高亮一下，水线回落。
- 抽书：把柜里任意一本拖回地面。
- 放错柜：书弹回，自动翻开封面，显示完整属性。

**可靠性要求（来自上一版审查）**
- 按事件增量更新，不在每帧或每次操作时整屏重建；弹窗创建后在关闭前保持不变。
- 任何重建或尺寸变化都先取消手里正拿着的书；丢失的 touch-end 不能让游戏卡在"拿起"状态。
- 存档失败（`saved=false`）时，结算界面显示"未保存"。
- 结算时只写一次通关记录，不在渲染中写存档。

## 4. 代码结构

### 4.1 逻辑层 `js/library/Pack*.js`（纯 JS，无引擎依赖）

| 模块 | 职责 |
|---|---|
| `PackLevels.js` | 3 关配置（标志、层、种子、`steps`、`refund`、模棱两可目标数）与生成器 |
| `PackBoard.js` | 柜、层的状态；`fit(book,cabinet,row)` 依次判定并返回 `wrong-cabinet` / `too-tall` / `too-thick` / `ok`（先判柜，所以放错柜时一律按放错扣 2 步）；放入、抽出、层满判定 |
| `PackRound.js` | 一局状态机：`pick`、`place(id,cabinet,row)`、`remove(id)`、`flip(id)`、`revive()`、`giveUp()`；步数、水位、胜负；`drain()` 事件队列 |
| `PackBots.js` | 规划型机器人（会翻开、会推断、按厚度规划）和乱塞型机器人（不翻开、贪心放入）；仅用于测试和调参，不进构建 |

- 复用 `LibraryRandom.js`。`LibraryProgress.js` 通过参数接收关卡列表和存档 key，新玩法使用 `rainyLibrary.pack.v1`。
- `scripts/cocos/sync-shared.mjs` 加入 `PackRound.js` 为同步入口。

### 4.2 画面层
- 新写 `cocos-pilot/assets/scripts/PackView.ts`：程序化搭建节点，灰盒色块加 emoji 花纹。
- `PinePilot.ts`：默认进入 `PackView`；`?library=1` 进入上一版 `LibraryView`；`?forest=1` 等参数进入旧森林。
- 旧的 `LibraryView.ts` 和 `js/library` 里的旧模块保留不动。

## 5. 测试与验收

- **单元测试**（`tests/pack-*.test.mjs`，`node --test`，先写测试）：
  - 塞满判定；高书进不了矮层；厚度超出剩余空间；抽出后靠紧。
  - 翻开 1 步且只能翻一次；放错柜 2 步并自动翻开；尺寸不合 0 步。
  - 层满退步且每层只退一次；用尽步数进入复活；复活仅一次；过关和失败判定。
  - 存档 key 独立，存档损坏或写入失败时不覆盖原存档。
- **生成器测试**：每关 50 个种子下，每柜书的总厚度 = 各层层长之和，且必定有解；第 2、3 关模棱两可的书达到目标数；第 1 关没有模棱两可的书。
- **机器人测试**：
  - 规划型机器人在 3 关、每关 50 个种子下全部过关，且不复活。
  - 乱塞型机器人在第 2、3 关超过一半的种子下用尽步数（证明需要动脑）。
- **构建验证**：`npm run cocos:build` 后在浏览器里实际拖完 3 关；`npm run cocos:build:wechat` 打包成功；`npm test` 除已知的基线失败外全部通过。
- **验收**：用户自己先玩。觉得"想玩下一局"后，再找 5 位没接触过项目的玩家，记录是否主动开第二局、卡在哪里、有没有塞满时的满足感。
