## 0. 关键决定（M0 已裁定，原冲突项已同步到对应文档）

下表的决定已由项目经理在 00 §8 裁定并同步到 01/03（标注裁决编号）；本文与各文档已对齐，无遗留待同步项。

| 项 | 决定 | 理由 / 影响 |
|---|---|---|
| 设计分辨率 | 720×1280，`ResolutionPolicy.FIXED_WIDTH`，世界与 UI 共用同一单位（下文记作 u）（裁决 D10，01 §18.1 已同步） | 与 01-gdd 一致，策划距离数值无需换算。更高的屏幕在竖直方向多看到一些世界，HUD 贴安全区边缘。SurvivorView 进入时设置、退出时还原为 PinePilot 的 375×812（MicroForestView 已有同样做法） |
| pt 换算 | 1pt = 720 / 屏幕宽度(pt) u；375pt 宽时 1pt ≈ 1.92u | 44pt 热区 ≈ 85u，统一取最小热区 88u（414pt 宽机型上约 50pt，仍满足） |
| 角色朝向 | 侧视帧左右翻转 + 行走时上下轻摆 2u（回应 R6） | 复用现有 8 帧行走，M2 不强制补绘俯视帧；向上/向下移动时保持最近一次左右朝向 |
| 镜头视角 | “侧视精灵 + 俯视地面”的常见割草游戏画法 | 敌人现有甲虫、蜗牛侧视帧可直接复用，只做左右翻转 |
| 暂停按钮位置 | 右侧，但在微信胶囊按钮下方（裁决 D12，01 §4 已同步） | 胶囊固定占右上角，按钮放在胶囊下方一行，不与之重叠 |
| 升级卡布局 | 三张卡竖向堆叠、整宽 | 竖屏横排三张会太窄，文字放不下、热区偏小 |
| 伤害数字 | MVP 不显示 | 200 敌人同屏时会严重遮挡且耗性能；受击闪白已够反馈 |
| 存档字段补充 | 新增 `vibration`（默认开）、`reduceFlash`（默认关）（裁决 D3，01 §13.3、03 §5.2 已同步） | 01-gdd 原只有音效开关，无障碍需要这两项 |
| 摇杆底座钳制 | 按下点离屏幕边或底部安全区过近时，底座中心内移到完整可见的位置 | 01-gdd 要求“底座出现在按下点”，补充边缘情况；偏移仍按手指相对（钳制后）底座中心计算 |

## 1. 美术风格与色板

### 1.1 风格

沿用仓库已有的“细腻自然绘本”方向（design/microforest-v1/art-direction.md）：轮廓清楚、低饱和的雨后林地、局部湿润亮边。新玩法在此基础上把“可读性”放在第一位：

1. 背景永远是最暗、最灰的一层，不抢眼。
2. 每一类游戏对象有固定的颜色家族 + 固定的形状语言，二者同时成立（色盲时靠形状，单色截图时靠明度）。
3. 只有对玩家有威胁的东西使用紫红/橙红；只有对玩家有益的东西使用青绿/水蓝/金色。
4. 特效轻量：不用全屏辉光、不用大面积粒子雾，雨丝只在背景层且透明度 ≤ 0.25。

### 1.3 密集场面下的区分规则

| 类别 | 颜色家族 | 形状语言 | 明度 | 层级（z 自下而上） |
|---|---|---|---|---|
| 地面、装饰 | 灰绿灰褐 | 不规则自然形 | 最低 | 0–1 |
| 孢子、露珠、林风 | 青绿 / 水蓝 / 白 | 菱形 / 水滴 / 旋涡，带 1.2 秒呼吸缩放 ±8% | 高 | 2 |
| 玩家落点预告 | 冷蓝虚线 | 虚线圆 | 中 | 3 |
| 危险预告 | 橙红 | 实心条纹箭头 / 扇形 | 中高 | 3 |
| 敌人 | 中灰 + 紫雾底影 | 生物侧影，脚下紫色椭圆雾影（宽 = 碰撞直径 × 1.3） | 中 | 4 |
| 小旅人 | 雾蓝赤陶 + 白描边 | 人形，脚下浅色圆形底影 | 中高 | 5 |
| 玩家攻击 | 暖白 / 琥珀 | 细长、带 3 段拖尾或旋转 | 高 | 6 |
| 敌方弹体 | 品红空心环 + 暗核 | 圆环，不旋转、匀速 | 高对比 | 7（最上层，保证永远看得见） |
| 受击反馈、HUD | — | — | — | 8–9 |

规则：
- 敌方弹体放在玩家攻击之上：玩家可以看不清自己的子弹，但不能看不清会伤到自己的东西。
- 拾取物放在敌人之下：被怪挡住只影响收集节奏，不影响生存判断。
- 敌人统一的紫雾底影是“这是敌人”的唯一共性标识；去掉颜色后仍可通过“脚下有椭圆雾影”识别。
- 精英：在紫雾底影外加一圈 4u 宽的脉冲描边（`#9B7BC4` ↔ `#F2C14E`，周期 1 秒，reduceFlash 时改为常亮）。

## 2. 竖屏布局与安全区

### 2.1 安全区计算

复用 PinePilot.measureSafeArea 的思路，SurvivorView 在进入与 `canvas-resize` 时重算：

```
scale       = 720 / windowInfo.windowWidth            // 设计单位 / 逻辑像素
capsule     = wx.getMenuButtonBoundingClientRect()
safeTop     = max(capsule.bottom + 8, safeArea.top, 24) × scale
safeBottom  = max(windowHeight − safeArea.bottom, 16) × scale
safeLeft/Right = max(safeArea.left, windowWidth − safeArea.right, 0) × scale + 24
```

- 接口调用失败（开发者工具、浏览器预览）时退回默认值：safeTop 88u、safeBottom 34u、左右 24u，不报错。
- 所有 HUD 元素贴 safeTop 以下、safeBottom 以上；世界画面铺满整屏（刘海和底部手势条后面仍显示地面）。
- 胶囊区域（右上角）不放任何可点元素。
- `game.json` 的 `deviceOrientation` 必须为 `portrait`（由开发在接入时确认；旧 MicroForestView 横屏玩法不在默认入口中）。

### 2.2 屏幕分区

```
┌──────────────────────────── 720u ──┐
│  刘海/状态栏            [胶囊····]  │ ← safeTop 以上：只显示世界
├────────────────────────────────────┤ safeTop
│ HUD 区（经验条、计时、暂停、栏位） │ 约 150u
│ ── 屏幕上 1/3：不触发摇杆 ──────── │ y = 1/3 屏高
│                                    │
│         世界 / 角色居中            │
│        摇杆可触发区（下 2/3）       │
│                                    │
├────────────────────────────────────┤ safeBottom
│  底部手势条                         │ ← 可按下，但摇杆底座被钳制到此线以上
└────────────────────────────────────┘
```

01-gdd 的“上 1/3 不触发摇杆”按整屏高度计算（不是安全区高度），保证不同机型手感一致。

- 主菜单 → 设置：以弹层形式出现在主菜单上，与暂停页的设置共用一个组件。

- 生命：只在角色脚下显示生命条，不在顶部重复（视线集中在角色附近）。生命 < 30% 时屏幕四边出现常驻暗红晕影 `#E86A5A` α0.25（不闪烁）。
- 武器/被动图标：右下角显示等级小字（Lv1–5，进化显示金色“★”）。HUD 栏位不可点击。
- 屏外指示：精英（紫色箭头 40u）、Boss（紫色箭头 56u + 雾壳小图标）、撤离点（金色箭头 56u + 太阳图标），沿安全区内缩 24u 的矩形边缘放置，指向目标方向。
- Boss 预警：出现前 2 秒，屏幕中上部横幅“浊雾正在聚集”（44u，紫底半透明），配 warning.wav。
- 撤离：撤离点光柱半径 50u；角色在内时，角色周围显示金色进度环（半径 40u，线宽 6u），2 秒填满；离开时进度环 0.2 秒内收回。
- 新手提示：首局底部（safeBottom 上方 200u）显示提示条 + 手指拖动示意动画，见 01-gdd 第 14 节。

## 5. 交互规范

### 5.1 摇杆

数值以 01-gdd 第 4 节为准，本节补充视觉与边缘情况。

### 5.2 触控热区

- 所有可点元素热区 ≥ 88×88u（≈ 44pt），相邻热区间距 ≥ 16u；“放弃”“重置”这类不可逆操作与主操作间距 ≥ 32u。
- 热区可大于视觉：暂停按钮视觉 64u、热区 88u；开关行整行可点。
- 按下态：缩放 0.96 + 亮度 −10%；松手在热区内才触发（TOUCH_END 命中判断），滑出热区取消。
- 局内只有暂停按钮可点击，其它 HUD 元素不接收触摸，避免抢摇杆。

## 6. 无障碍

1. 色盲友好：1.3 节每个类别都有独立形状（菱形经验、水滴回血、空心环敌弹、条纹箭头危险、虚线圈己方落点、紫雾底影敌人）；升级卡、强化等级、开关状态都配有文字或实心/空心符号，不只靠颜色。
2. 明度分层：灰度截图下仍能区分“背景（暗）< 敌人（中）< 玩家攻击、拾取物、敌弹（亮）”。
3. 设置项：音效、震动、减弱闪烁，三项在主菜单设置和暂停页都可改，即时生效，写入存档。
4. 文字：最小 24u；正文与背景对比度 ≥ 4.5:1，大字 ≥ 3:1。
5. 单指可完成全部操作，无长按、双击、多指手势。
6. 声音不是唯一信息来源：Boss 预警、受伤、升级都有视觉反馈。
7. 验证方式：Chrome DevTools “Emulate vision deficiencies”（红绿色盲、蓝黄色盲、全色盲）对 3 张截图（0:30、6:40 满屏、Boss 战）检查。完整的无障碍符合性还需要真机和真实用户测试，本文只覆盖设计层面。

## 7. 合规检查（UI 侧）

- 合规扫描对象与词表以 04 §7.1 为准（裁决 D16）：扫描范围 = data/strings.js 与表现层中文 UI 字面量；“死亡/血/尸”类词仅限面向玩家文案，资源帧名/字段名/日志不在扫描范围。
- 文案：统一“净化 / 驱散 / 撤离”；不出现“击杀、消灭、死亡”（失败用“被浊雾笼罩”）；不出现“吃、食用、采食、美味”与蘑菇/菌的组合。
- 图标：回血类只用水滴和太阳；任何蘑菇图形只出现在武器（菌伞）、被动（菌丝、菌帽）、敌人（迷途菌灵）和场景装饰。
- 特效：敌人消失为光点/水汽；无红色液体、碎块、尸体；受伤晕影是屏幕边缘颜色，不画在角色身上。
- 迷途菌灵净化时用金色孢子光（01-gdd 第 9 节），区别于普通敌人的白色光点。

## 9. 几何占位先行（M1）

M1 不等美术：除复用帧外，所有对象用 `Graphics` 按第 8 节“占位形状”绘制，但必须遵守最终的颜色家族、形状语言、显示尺寸和层级（1.2–1.3 节）。这样：

1. 可读性和色盲区分从第一天就能被测试工程师验收，换正式图只是“同形同色换皮”。
2. 碰撞与显示尺寸提前对齐，M2 替换素材不需要改逻辑。
3. 性能：大量相同几何体应预渲染成纹理后用 Sprite 批量绘制，而不是每帧 200 个 Graphics 重绘；具体方案（运行时 RenderTexture 或预先导出占位 PNG）由 03-architecture 决定，本文只要求同类对象共用一张纹理以便合批。

## 10. 验收标准（UI/UX）

1. 在 375×667、390×844、414×896 以及有刘海/手势条的机型（开发者工具模拟 iPhone X 系列）上，所有 HUD 和按钮都在安全区内，且不与微信胶囊重叠。
2. 所有可点元素热区 ≥ 88×88u，相邻热区间距 ≥ 16u（测试用 debug 绘制热区框截图检查）。
3. 屏幕上 1/3 按下不出现摇杆；下 2/3 任意位置按下出现摇杆，靠边按下时底座完整可见；第二根手指不改变移动。
4. 暂停、升级弹出时摇杆隐藏，恢复后不按屏幕角色不移动。
5. 升级卡在弹出 0.4 秒内点击无效，之后点击整卡任意位置都能选中；进化卡带金框和“进化”文字。
6. 6:40 满屏截图在红绿色盲、全色盲模拟下，测试人员能指出：自己、敌人、敌方弹体、孢子、露珠各一个例子（5/5 正确）。
7. 关闭震动后全程不调用 `wx.vibrateShort`；开启减弱闪烁后，角色无敌期间不闪烁、受伤晕影不闪、敌人受击不闪白。
8. 三项设置重启后保持。
9. 全部界面文案通过第 7 节合规检查（测试用关键词扫描文案表）。
10. 启动页显示健康游戏忠告与适龄提示入口；首次启动出现隐私授权。
11. M2 替换正式素材后，同一位置截图的对象尺寸与 M1 占位相差 ≤ 10%。

可测试性：第 2、3、4、5、7、8 条可在表现层写 cocos:test 冒烟用例或手动检查；第 6、11 条需人工截图评审；安全区计算建议抽成纯函数（输入 windowInfo、capsule，输出四边距）放在 js/survivor/，用 node --test 覆盖默认值与刘海机型。
