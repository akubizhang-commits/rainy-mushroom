# 雨后森林幸存者 · 项目计划（项目经理）

版本 v0.5 · 阶段 M2 后半 / Sprint 3 第一批 · 状态：M1 原型完成并经用户试玩；S2 自动化提测通过、真机待用户确认（reports/sprint-2-test-report.md）；用户已放弃换方向、继续优化本作，S3 看板见 09（S2 见 08，S1 见 07）
产品名：雨后菌语（以账号登记名为准）。AppID 沿用 project.config.json 现值，不新建账号。

## 1. 项目目标

在名称已锁定的账号下，把玩法换成与“雨后、蘑菇、森林”主题一致的割草生存游戏：
小旅人在雨后森林被虫群围攻，自动攻击，拾取孢子升级，三选一技能，一局 5–10 分钟。
成功标准：真机可玩、包体合规、内容合规，能用新玩法更新「游戏内容介绍」并通过审核。

## 3. MVP 范围

做：
- 1 张雨后森林地图（可循环滚动地面 + 少量障碍：倒木、蘑菇丛作为掩体装饰）。
- 1 名角色（小旅人），虚拟摇杆移动，自动攻击。
- 5 种普通敌人（蚊蚋、甲虫、灰蛾、蜗牛、迷途菌灵）+ 1 个精英（甲虫强化版，5:00 出现）+ 1 个 Boss（浊雾巨蜗，7:00 出现）。（裁决 D1，见 §8）
- 5 种武器 + 6 个被动强化，升级三选一；孢子作为经验掉落。（裁决 D2，见 §8）
- 一局 8 分钟目标时长，胜利/失败结算、局外少量成长（1 条货币 + 3–5 项永久强化）。
- 本地存档、暂停、音效开关、隐私与适龄提示。

明确不做（MVP 阶段）：
- 多角色、多地图、联网排行、PVP、服务端（“后端”仅限存档/广告/隐私服务封装）。
- 血腥表现：敌人被击败用“化为水汽/光点/孢子”消散，无血液、肢解。
- 任何“采食野生菌回血/求生”机制；回血来源改为雨滴、露水、营地篝火等。蘑菇只作为场景、技能主题（如“菌伞护盾”）或孢子光效。
- 付费内购；广告仅保留可选的复活/双倍结算激励视频，M3 前评估。
- 旧玩法的新功能开发。

## 7. 协作规则

每个 Sprint 约 1 周，固定四步：

1. 设计：项目经理从里程碑中拆出本 Sprint 任务；策划写需求与验收标准，UI/UX 给交互与素材规格，架构师确认接口与影响面。任务进入开发前必须有可测试的验收标准。
2. 开发：逻辑先写在 js/survivor/ 并配单元测试，再做 Cocos 表现层；不手改 shared/ 同步副本，修改后运行 `npm run cocos:sync`。每个任务一个小提交，提交说明遵循现有风格（feat(survivor): ...）。
3. 测试：测试工程师做代码审查，运行 `npm test`、`npm run cocos:test`、`npm run cocos:build:wechat`，检查 package-report.json 包体，并在微信开发者工具或真机试玩，按用例出报告。未通过的任务退回开发。
4. 复盘：项目经理汇总完成情况、缺陷、性能数据；运营补充玩家视角建议；更新本计划的风险与下一 Sprint 范围。

通用规则：
- 文档优先：需求变更先改 docs/survivor/ 对应文档，再改代码。
- 范围冻结：MVP 之外的想法记入“待办池”，不进入当前 Sprint。
- 合规一票否决：任何角色发现血腥或野生菌食用暗示，可直接阻止合入。
- 破坏性操作（删除旧代码/素材、改默认入口、提交提审）需用户确认。
