这些区间有嵌套，样本次数也不同，**不能相加作为总帧 CPU**，不同区间的分位数更不能相加。draw 是同步绘制调用的 CPU 区间，不等于 GPU 时间；persist 包含事务校验、编码与调用存储，本样本使用内存存档，不代表手机真实持久化 I/O。0ms 或很小的读数受计时精度影响，不代表零成本。现有分段没有把深拷贝、校验、编码、排序逐项分开，所以不足以决定删除哪次拷贝或跳过哪次排序。

现有内部目标是活跃帧 P95≤20ms、P99≤33.3ms，并以 60FPS 为目标；它们是项目目标，不是 Tap 平台硬规定。这段普通战斗的两个分位数落在目标内，startup P95略高，但短样本、桌面调试包和静止初始配装均不满足正式比较条件。

两段 Queue 诊断均为 **0 个 failed**：startup 有 8 次 transport ready、8 次 binding ready；战斗有 83 次 transport ready、95 次 binding ready，另有 7 次 optional-audio ready。Resource Timing 中唯一 HTTP 404 为 `/favicon.ico`，累计只出现一次，不是游戏素材；其余 startup 48 条、战斗累计 241 条均为 HTTP 200。主代理浏览器操作记录中的 deprecated API 警告属于已知告警，不能解释为已消除，也不冒充素材加载失败；原始 JSON 本身没有完整 console 日志。

## T08 的触发、停止与回归标准

当前仅识别到高源像素预算候选，未获得“零消费者资源仍长期占用”的证据，**不执行缓存淘汰**。下面是后续试点的执行门槛，不是本批数据已达到的结果。

1. 先对最终同一构建记录设备、渲染设置、资源 manifest、缓存/网络条件与可复用场景。完成至少低/中/高档目标设备基线；内存预算由真实设备首轮读数和告警确定，不在此猜测统一 MB 上限。
2. 在相同资源路径、相同返回场景下做 30 次进入/暂停/撤退/再进；在第 10、20、30 次记录同等 GC 条件的 Heap、可用进程内存、按组引用与实际消费者。若后段每次仍有新增、无消费者对象不回收，或目标设备出现可复现内存告警/超预算，再以持有链和组引用证明原因。仅有一次峰值或源像素之和不满足条件。
3. 原因定位到具体组后，先试点妖猪或单个技能组的 acquire/release 所有权。确保共享资源的所有使用者均已解绑，自建 SpriteFrame/Texture 与队列引用各自有配对释放，晚回调按 generation/token 失效；不修改画面分辨率、Boss/狂暴比例、帧数、动画时间或技能表现。
4. 任一消费者被提前释放、重进白图/缺图、旧回调绑定新场景、战斗中意外进入阻塞加载、离线不能重进或明显重复下载抖动，立即停止并回退试点。所有权无法证明，或比较中的网络/GC/资源集合不一致，也先停止效果结论。
5. 验收要求相同场景 30 次循环的引用/节点和资源数量在预热后趋稳，目标设备无内存告警；内存峰值或稳定驻留的改善大于基线重复运行波动，且重进加载时长、错误与传输量没有不可接受回退。同步覆盖切层、暂停、死亡、后台恢复、弱网重试和 2 小时运行；按真实显示尺寸对比普通/Boss/狂暴、标签、裁剪、脚底、特效与死亡恢复。任一画质退步或玩法变化即不通过。

## T09 的触发、停止与回归标准

当前 snapshot P95=0.4ms，persist P95=3.6ms，draw P95=1.3ms，只表明这个短样本的区间分布；**不足以支持深拷贝、事务校验或排序重构**。

1. 先补最终同构建、同设备、同 seed、同输入的普通/多怪/多技能/特效密集场景，每场景 10 分钟×3 次。建议将“至少 2/3 次活跃帧 P95>20ms 或 P99>33.3ms”作为进入热点调查的具体门槛；这只是本轮建议的调查规则，不修改既有验收目标，也不单凭这一门槛决定代码改动。低频长卡顿仍须独立记录与定位。
2. 将长帧与 CPU/分配时间线对齐，分别测目标选择/深度排序、快照构造、事务复制、校验、编码和真实存储调用。只有重复实验将成本归到候选调用，并能提出可验证的收益假设，才启动对应小改动；draw 分段或一次 63.8ms 帧间隔不能代替排序调用栈证据。
3. 排序热点先验证脏标记与“不变时跳过排序”，保持稳定排序的 tie-break 和节点顺序；拷贝热点先证明对象所有权、冻结边界和消费者不修改共享状态，再考虑减少重复复制。不得以删校验、改变模拟 tick、改变碰撞/命中顺序或降低特效换取分数。
4. 在代码修改前保存固定 seed/输入回放基线。事件序列、敌人/弹道处理顺序、击杀/掉落、属性/伤害、奖励和最终存档必须一致；写入失败时原始字符串与内存状态不变，重复 finish 不领奖，陈旧 Store 不覆盖新档，跨模式键隔离、暂停快照和恢复行为均须通过。任何一项不一致立即停止并回退。
5. 同设备 A/B 各重复 3 次；先用基线运行间波动约定可识别的最小收益，再比较候选区间与帧 P95/P99。收益不稳定、没有超过噪声，或把时间/内存成本转移到其他路径，就不合并该优化。正式回归还须通过合法多技能和压力场景、2 小时运行及 30 次循环；图片/特效和数值保持原样。
