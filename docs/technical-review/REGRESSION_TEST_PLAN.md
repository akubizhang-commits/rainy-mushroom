## 自动化门禁修复方式

先让VM夹具加载实际新增依赖，再跑全量；规则失败分为“现行缺陷”“过期断言”“证据不足”。每项须关联现行需求，禁止为了全绿调整业务数值、批量skip或删除保护性断言。当前291项缺类错误只是分类，不代表剩余272项全是生产Bug。

特别保留：存储setItem抛错后原始字符串和内存状态不变；损坏档只读；旧schema只重置本模式键；重复finish不领奖；并发旧Store不能覆盖更新；道具、买卖、锻造、突破在失败时不能扣款或增物。

## 场景矩阵

| 场景 | 操作与覆盖 | 必采指标/断言 |
|---|---|---|
| 首次启动 | 清应用缓存、新账号/新档、冷网加载3次 | TTI定义为加载遮罩消失且按钮可交互；请求字节、错误、峰值内存 |
| 主界面静置 | 宗门10分钟、详情/背包/藏经阁切换 | 帧间隔、节点数、纹理数、Heap趋势、周期存档耗时 |
| 普通战斗 | 第1层固定seed正常操作 | AI、攻击、拾取、存档、帧P50/P95/P99 |
| 多怪战斗 | 选现行规则合法最大同屏场景 | CPU分段、Draw Call、碰撞/目标选择正确性 |
| 多技能 | 已有技能合法组合与武器切换 | 弹道/命中/法力/冷却/装备加成、掉落一致 |
| 特效密集 | 已有组合合法触发；普通/Boss/狂暴分别看 | GPU/纹理峰值、遮挡、标签、裁剪、脚底、死亡恢复 |
| 长时挂机 | 至少2小时，多层循环；记录热降频 | 内存斜率、温度/电量（工具可用时）、没有奖励重复/卡死 |
| 重复进出战斗 | 30次进入/暂停/撤退/再进 | 节点与引用趋稳、无重复监听、无晚回调绑定旧节点 |
| 场景切换 | 宗门/背包/藏经阁/突破/战斗全路径 | UI操作、属性一致、加载耗时、资源404 |
| 后台恢复 | 10秒/5分钟/锁屏/电话或广告打断 | 不后台推进；恢复输入清空；时间不跳跃；只结算一次 |
| 网络异常 | 404/500/超时/断网/恢复/缓存不完整 | 必需资源可重试、可选音频不阻塞；不假成功 |
| 存储异常 | 配额、读失败、写失败、损坏、刷新中断 | 只读/原子性/重复领奖/跨键隔离 |
| 横屏适配 | 常规横屏、844×390、平板、缺口两方向 | 安全区、按钮命中、竖屏阻止战斗推进 |
| 广告 | 完播/早退/无填充/重复close/失焦/超时/保存失败 | 正确恢复；奖励最多一次；无广告仍可玩 |

## 设备与比较条件

至少低/中/高三档真实Android设备；iOS覆盖以实际发行渠道支持及用户目标为准，不把微信的iOS核验直接搬到Tap门禁。每次记录机型、系统、Tap版本、温度/电源、屏幕/DPR、画质、源码和资源manifest、相同seed和输入。模拟器/桌面单列，不与真机混算。

每个性能场景预热后采样至少10分钟，重复3次；冷启动另测。渲染工具不支持GPU时间则填“不可用”，不拿CPU帧时替代。内存要同时观察JS Heap、进程和纹理估算，同等GC条件比较；不以一次Heap下降证明无泄漏。

只在同场景同设备比较优化前后。固定回放比较事件序列、击杀/掉落/属性/奖励/存档，UI截图按真实显示尺寸比较。物品图标接入变更须执行`python3 scripts/art/item_icon.py --check`；本轮无素材变更未以该检查宣称全库合格。
