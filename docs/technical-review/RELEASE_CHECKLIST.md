# TapTap发行候选检查清单

当前状态：**不可作为已通过上线验收的候选版**。以下是未来门禁，不是本轮已完成项。

## 发行输入

- [ ] 确认普通小游戏或H5小游戏的实际发行形态、目标系统/设备。
- [ ] 完整源码基线（含未跟踪现行文件）已固定，工具链/插件/构建脚本/配置/资源哈希已记录。
- [ ] 正式包关闭开发UI、辅助偏好、发资源和QA钩子；双层权限负测通过。
- [ ] 根JS和生成shared一致，禁止手改生成副本。
- [ ] 按固定版本Creator与Tap转换插件产出唯一候选，摘要一致；独立输出不覆盖其他验收包。
- [ ] 完整类型/编译检查结果明确；有效回归套件无未解释失败。

## 平台和内容

- [ ] Tap真实AppID及账号资格已核验；未复用微信AppID/旧森林资料。
- [ ] 从后台核实主包/分包/总包及单文件限制，并将实际数值落入Tap检查脚本。
- [ ] 横屏配置、安全区、触摸和无DOM环境通过。
- [ ] 白名单/HTTPS/CDN证书/缓存更新及回滚通过；网络HTTP错误正确处理。
- [ ] 本地1MB单键/10MB总缓存边界和清理恢复方案验证（实施时再核对官方最新要求）。
- [ ] 隐私、年龄、内容资质、素材权利、商店资料按Tap当前后台要求核验；不能拿微信旧清单替代。
- [ ] 广告如启用：广告位审核通过，单例适配、完播判定和幂等奖励经真机验证；如不启用明确关闭。
- [ ] 数据统计/崩溃日志具备版本、场景、错误码，最小化采集并明确保留周期。

## 运行验收

- [ ] REGRESSION_TEST_PLAN各现有功能矩阵通过，P0/P1清零或有明确不发布相关功能的决策。
- [ ] 十类性能场景覆盖真实低/中/高设备，记录原始trace，达到约定预算。
- [ ] 30次切换和至少2小时运行无异常内存增长/卡死/重复奖励。
- [ ] 资源加载故障/断网恢复/背景恢复/存档写失败均通过。
- [ ] 普通怪、Boss、狂暴、死亡、暂停及技能画质按原验收规范通过，无为瘦身造成的表现退化。
- [ ] 四种体积口径清楚，TTI独立实测；无未确认缺失素材。

## 发布及事故处理

1. 冻结候选源码与资源manifest，归档构建日志、测试结果、机型矩阵和已知限制。
2. 在Tap开发版本中导入同一候选，内部真机验收；用户明确批准后才上传/提审/安排公开发布时间。
3. 按后台要求提交资料并核查实际上线时间；审核状态变化不自动等同于内部验收通过。
4. 保存上一通过包、CDN资源版本、开关配置和诊断符号；不要删除付费源素材。
5. 上线后按buildId监控启动失败、资源失败、存档失败、广告错误及重复奖励告警。先关闭可选广告/远程功能，再评估回滚整个包。
6. 回滚必须保留玩家已获得收益与存档数据；开发期允许旧档重置不自动延伸到正式上线后的兼容策略，上线前重新确认。

本轮没有上传、提交审核、开通广告、修改账号或发布任何版本。
