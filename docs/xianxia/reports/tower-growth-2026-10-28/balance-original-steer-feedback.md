# 给主线程与 Gauss：成长实战压力反馈

**版本门禁未通过：** 最新全量运行期间 TowerCampaign 再次变更，脚本退出码3、状态 `source-changed-rerun-required`。已完成的实际战斗与消费测量保留；不能据此宣称当前最新集成版本通过。并行修改收口后需执行 `node scripts/verify-tower-growth-balance.mjs --repeat-check`。

基于 `balance.json` 的三种子完整测量；脚本与 Run/Campaign 数值隔离。**全部通关不代表平衡通过，也不代表真人可接受。**

## 核心发现

1. **第三层有显著重复劳动压力。** 六次自然流程在第三层均需要9–10次尝试，前8–9次全部止于已清19/20波。当前策略依靠失败保留的真实收益提升到更高境界，再通关；不能写成平滑一次性九层成长。
2. **36点流派效能不相等。** 同种子、XP10920、HP120、素问剑品质1/强化4下，贯穿路线平均耗时比御剑36点长39.26%，剑阵长29.82%。这反映该移动策略与整层刷怪/覆盖的组合，不能仅凭此直接改技能系数。
3. **30点不是硬门票缺口。** 30点自然路线三种子均完整到九层，没有购买研习点；九层均以实际30点出战并一次通关。额外首通点自动授予但不花。36点自然路线首次挑战九层实际为34点，过关及回宗后才到36，报告明确分开。
4. **四套fixture只证明容量和同装备战斗对照。** 它们显式构造满境界、通九层、教学完成和资源；然后通过 `store.act` 逐次真实购买经卷、研习和等级。不得称为从零自然养成。

## 教学、复现及限制

- 三种子首层第1波均在12.100s清完并绑定剑气；第3波均在39.950s绑定万剑。剑气首次实际动作21.800s，万剑49.583s；存在约9.7s的等怪/进入射程间隔，不是学会当刻就命中。
- 首次自由SP消费在80s暂停检查点；这是测试策略安排，不代表UI必须等待80s。教学绑定不消耗自由SP。
- 六次自然流程共116次实际战斗，另12组fixture；附加御剑36种子1复跑，完整终局快照、交易台账哈希与指标完全一致。三种子均为预先固定，未筛选胜者。
- 三十点种子7的总用时更长，需结合逐层失败记录审阅；不能把某一对照均值直接解释为所有场景的优劣排序。
- 第一、第二批运行前后核心源码哈希一致（保留于 balance-before-campaign-update.json 与 balance-before-run-update.json）；其后检测到并行更新，第三批运行期又出现Campaign变更。三批自然/fixture结果对象完全一致，但最新集成门禁仍需重跑。steer函数体与旧journey完全一致；导入本脚本不会自动运行或覆盖旧报告。helper以1/60秒调用引擎/策略，旧脚本为1/30秒；这是采样与控制频率差异。
- bot无人的反应延迟，可读取全部敌人、预警区及弹道；视口矩形不是设备渲染/可见性验收。本结果没有多人盲测或真人可玩性结论。
- 早期层最多12次尝试，九层最多40次；本批九层不需要重试，故未声称测过40次失败边界。若失败预算耗尽会保留报告，不改HP或强行pass。
- 不擅改境界27、HP、怪物、资源、装备30%上限或任何硬规则。建议主线程/Gauss先复核三层Boss压力，以及贯穿/剑阵与趋近/避险策略的交互，再决定是否开展独立参数校准。
