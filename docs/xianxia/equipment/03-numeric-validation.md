# 装备数值契约与验证

2026-10-26；数值设计交付，未接入运行时。所有验证仅为下述契约的数学检查，不是玩法模拟。范围为本文件和 `../reports/equipment-quality-v3-2026-10-26/`。

依据：[20号装备方案](../20-equipment-and-replayability.md)、[职业共享规则](../classes/00-shared-rules.md)、七职业条目、`js/survivor/data/permanent.js` 与 `Meta.js`。本次任务明确缩小20号稿预算：整套顶配相对同状态无装备，连续量输出≤18%、静态生命/EHP≤8%，乘积≤27.44%，保留2.56个百分点余量。当前验证为四品质v3；旧三品质6,965,142行记录留在equipment-detail-2026-10-26，仅作历史，不代表新增下品已验证。**不等于胜率、存活时长或通关速度最多提高30%。**

## 1. 本轮替代口径

| 槽位 | 下品 / 中品 / 上品 / 极品 | 槽淬炼 | 整槽最大贡献 |
|---|---|---|---|
| 武器 | 伤害3% / 4% / 6% / 8% | 0–4级，每级1个百分点 | 基础12%，唯一条件特性再加最多6个百分点，总计18% |
| 法衣 | 最大生命1% / 2% / 3% / 4% | 0–4级，每级1个百分点 | 8%，不提供减伤、回复、护盾或移速 |
| 佩饰 | 收藏/表现 | 无数值淬炼收益，不收费购买空等级 | 0；无拾取、经验、重抽、触发效果或隐含效率增益 |

武器特性在同一个装备加法预算内，绿蓝紫金保留同一条件及强度。只允许条件满足时增加已有事件的伤害量；单事件所有装备条件合计≤6%，不能多件、多标签各加6%。目录特性T取−3%、0或+6%；脚本扩大到−3至+6每个整数百分点，合计e=0–18%，另含无装备e=0。任意连续 `−0.03≤T≤0.06` 的上界由单调性覆盖。反向集合只应用一次−3%，不能同时应用正负分支。

条件只能筛选原有技能/目标/事件，不能创建事件、增加触发资格、频率、暴击、冷却收益、范围、目标数、弹数、DOT跳数或召唤数。不能改攻击优先级或选卡概率以偷偷放大预算。不同武器条件覆盖可以有取舍；不同品质基础数值提升允许同身份金优于蓝。

20号稿的飞剑4/7/10%、淬炼+5、每级2%、法衣绝对HP、回血/减伤/移速特性、佩饰拾取/追加伤害/重抽，均不沿用。原淬炼五级价格表也不能直接搬入四级系统；新四级价格与灵石道基竞争另行冻结，不能宣称已验算完整经济。

**明确替代原“道基和装备同一加法项”的推荐。** 既有道基不扣回、不改公式，完整无装备攻击基准叫 `A0`，装备独立且只进入一次结算：

```text
e = rarityWeaponBase + weaponLevel × 0.01 + eligibleTrait
装备时0.01 ≤ e ≤ 0.18；无装备e=0
A_equipped_for_this_event = A0 × (1 + e)
H0 = 同状态移除三件装备后的最终最大生命（含道基、境界、心法、丹药）
Hmax_continuous = H0 × (1 + eh), 0 ≤ eh ≤ 0.08
```

例如只含满道基25%时，攻击无装备125，装备顶配147.5；相对该玩家无装备仍为1.18。此前加法方式得到143，不能混用两种面板。若技能还有暴击/易伤等，先以原规则结算出完整无装备事件 `X0`，统一出口才应用装备；不要真的将已含装备的 `A` 写回 `stats.might` 再乘一次。

## 2. 同状态反事实与整数事件上限

定义同状态：同owner、技能等级、施放、目标UID/位置/状态、道基、心法、境界、丹药、原有暴击结果、减伤/易伤、随机结果和命中次数；只移除装备。不是重新跑一局后比较不同目标和不同事件。

`X0≥0` 是无装备最终舍入前伤害；免疫、系数0等在这里归零。先调用**既有统一舍入函数**得到 `n0=RoundBaseline(X0)`；检查脚本用非负half-up作为明确模型。接入时必须核对真实函数，不能假定实现已相同。

**已接受并冻结的唯一默认是严格整数增量模式：**

```text
ePct ∈ [0,18]                 // 本版按整数百分点配置
bonus = floor(n0 × ePct / 100) // 用整数运算；扩大精度时改用基点/固定分母
nEquip = n0 + bonus
assert 100 × nEquip ≤ 118 × n0
```

该规则替代“连装备一起四舍五入”的末次舍入口径；是接入前需主稿和共享规则显式采纳的差异，不声称旧规则已满足。n0=0时严格为0；n0=1–5时顶配也可能无额外整数伤害，这是严格事件上限的必然取舍。不要强制最低1点装备伤害。实际扣HP再取 `min(targetHP,nEquip)`；同目标HP下不放大倍率，过量伤害不计有效伤害。不得用舍入后的伤害反推快照A。

**反例：** X0=1.49，无装备四舍五入1，乘1.18后四舍五入2，比同状态整数基线提高100%。仅验证浮点倍率≤1.18无法发现这一问题。

不使用小数余量账本，不修改权威HP/伤害精度。此前探索的小数累计模式已否决：它允许单事件1→2，不满足本次逐事件严格契约；相关测试已从接受结果移除。直接给合成伤害四舍五入也不采用。

当e=0或装备适配关闭时直接返回原整数n0，必须逐位保持原零装备Golden结果、事件数与RNG顺序；不能先重算旧伤害再声称等价。缺失可验证的无装备来源、重复应用、非法参数或整数乘法可能超出安全范围时，关闭该技能的装备适配并返回原基线、记录诊断，不静默夹值或改用另一种舍入。基线自身非法应沿原运行时错误策略处理，不能凭空构造伤害。

整数实现采用安全整数或BigInt；本版ePct为整数百分点，导入小数配置时明确映射并校验到整数，不靠浮点乘100截断。未授权精度的词条拒绝入表。对任意有限事件集合，逐事件不等式可求和，因此不会由多次小伤害累计出额外超预算，但小额增量被舍弃的损失可以随事件数累积；**不承诺长期贴近18%收益**。

## 3. 快照与衍生伤害：每个事件只一次

事件数据分离 `baselineAttackSnapshot`、`baselineDamage`、`equipmentPercent`、`equipmentApplied`；建议纯函数 `finalizeDamage` 只接收未结算基线事件，拒绝已结算值再次输入。终值不是后续技能的攻击基准。

| 类别 | 无装备基准读取时刻 | 装备处理 |
|---|---|---|
| 直接攻击 | 该技能原定快照时刻 | 命中结算一次；原暴击授权不变 |
| 法修DOT | 施法A0快照 | 跳伤从A0算，不从已放大直接伤害算；每跳一次 |
| 御兽 | 宠物每次攻击开始A0；附毒沿用该攻击A0；龙影沿用施放A0 | 宠物HP/治疗不随玩家法衣成长；召唤攻击/毒各自事件一次 |
| 阵修DOT | 按条目每跳读取当前A0，其余参数维持布阵快照 | 不能把布阵时装备A再当每跳A0 |
| 邪修咒DOT | 最近成功附咒的A0快照 | 保留层数/刷新/到期顺序，只在末次伤害出口加预算 |
| 反伤、二次爆发 | 原技能的无装备A0或显式baseline来源量 | 不使用装备后实际伤害作为输入再乘；不增加事件/触发边 |

装备配置开局冻结，条件是否满足默认按命中状态判定；若身份需要施放时条件快照，必须显式记录并始终使用同一判定。两者都不能叠加。装备不将DOT变直接攻击，不给反伤暴击，也不解禁二次触发。

示例：100A0的20%毒，顶配应由20基线结算，连续量23.6；不是118×20%×1.18=27.848。如原技能明确基于前次有效伤害，需同时保存前次**无装备反事实有效伤害**；没有这个量时不得宣称继承一次已经证明。同状态外的击杀提前、反伤触发次数、有效伤害治疗资格发生改变仍属于玩法验证。

## 4. 生命、破境和自损：保留动态例外

**已接受普通Hgear/currentHP模型，否决额外reserveHP与coreHP模型。** 不拆第二条生命，不引入不可补充储备，不改变破境满血体验；此前储备转移测试已从接受结果移除，不再主张生命周期有限资源证明。

```text
H0 = 完整无装备最大生命，保留原权威精度
Hgear = H0 + floor(H0 × E)       // 只向下取整装备新增HP；E≤0.08
开局生命=Hgear；普通currentHP存储，不拆储备
有效治疗量=min(原规则按H0求得的治疗量, Hgear-currentHP)
破境：更新H0/Hgear，并沿原有效破境事件把currentHP补满至Hgear
```

连续预算写作H0×(1+E)，上述整数增量只是保守实现，不能把原H0也重新取整。零装备返回原H0；H0=0无装备生命增量。无效H0走原错误策略。除开局和原破境事件外，Stats重算/暂停/重绘/外观切换不能凭空补血；普通最大生命变化沿既有规则，不新增满血事件。

所有非破境的百分比治疗、掉落百分比治疗、持续回复生成量及上限、盾量及在身盾上限、生命转伤、技能自损和退款窗口均读取H0。普通固定治疗保留原值；持续回复≤H0×1%/滚动秒，盾≤H0×30%，血术另有H0×3%/滚动10秒上限。装备不提高宠物最大生命、治疗或盾量。有效治疗仍可能因更大缺口而减少溢出，这是动态差异。

生命比例条件按 `min(currentHP,H0)/H0` 求值；H0=0时不允许需生命的施放，不除零。血术接受时冻结H0_cast、已修正扣血比例及cost：

```text
cost = ceil(H0_cast × correctedCostRate)
接受条件：min(currentHP,H0_cast) > cost + 0.20×H0_cast
扣血：currentHP -= cost；绕过盾/减伤，不触发敌方受击
退款上限=floor(actualCost/2)，不因后续H0改变重新计算已付cost
```

延迟结算沿该施放快照，退款仍受原有效伤害资格、当前H0窗口等规则约束，不能提前多退款。e只修正攻击，不把伤害增量换成比例吸血。额外生命可能延迟跌破阈值，必须测动态影响，不能据min口径声称所有额外施放已经排除。

**破境补满Hgear是明确保留的动态例外。** H0=100、E=8%，三次从相同空缺补满可累计多恢复24HP，而非仅8HP。脚本记录这个反例；它证明不能从8%静态HP推导整局只多8HP资源。真实破境还受存活与事件时序约束，此反例不是实战模拟。静态预算与原破境体验同时保留，不对整场治疗、TTK、存活时间作30%保证。

## 5. 上限、品质比较与固定预算

令相同无装备承伤倍率 `r>0`，常态 `r≥0.4`、明确短时特殊状态 `r≥0.25`，装备不改变r：

```text
EHP0=H0/r
EHPequip≤1.08H0/r
静态输出×EHP比≤1.18×1.08=1.2744<1.30
```

减伤60%/75%来自共享设计，旧运行时是否已实现另验。完全无敌时r=0，EHP比未定义，不能除零后算通过；该状态比较装备不得改变持续时间/触发条件。

同一身份/同一事件条件比较品质必须固定T。极端跨条件比较的最强金满强T=+6，对蓝零强T=−3为 `1.2744/(1.01×1.02)=1.237041…`，只是装备端点包络，不能称为品质差距；同淬炼/同T的品质比较另行穷举。此为连续上界比较，不能拿最强蓝条件关闭与金条件开启声称“品质本身提高这么多”。严格整数模式可能让小额蓝收益消失，应分别展示，不保证所有整型品质比也≤连续端点比。下品反向集合也不会产生负加成，因此金/蓝整型比仍受金/无装备≤1.2744的整体上限约束。

固定预算归一化用于比较职业或身份条件：在伤害结算**之前**将两边装备e、eh均设0，保留同道基、同构筑、同目标和原随机结果；或纯连续数学中除以各自 `(1+e)(1+eh)`。不能除整数实测总伤害反推真实基线，不能统一加怪HP后宣称无膨胀，不能因装备省选卡/省时间后又给它额外构筑预算。脚本验证连续归一化恒等式和严格模式零预算，未模拟固定时间击杀。
