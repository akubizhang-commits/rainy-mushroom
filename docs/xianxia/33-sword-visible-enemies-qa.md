# 剑修密集战斗：敌人显示容量修复

2026-10-27，Alpha 验证阶段。

## 问题与修复

浏览器注入200只同屏普通敌人时，逻辑仍有200只，显示池却只提供160个节点。精英光圈与身体共用该池，还会进一步挤占身体显示。因此可能出现看不见但仍参与战斗的敌人。

`SurvivorBattleArt.ts` 将敌人显示容量改为 `Math.max(LIMITS.nodes.enemies, 2 * LIMITS.pools.enemies)`，当前上限404。202个逻辑敌人即使全是精英，也各有身体和光圈。节点按需创建，重开后隐藏并复用，峰值缓存不会立即释放。该修复覆盖共用渲染器的经典与修仙模式，未修改生成数量、伤害、掉落或选卡规则。

## 验证

- 全量845项测试通过，源码检查和web-mobile构建通过。
- 新增2项真实渲染器回归：202只普通敌人、202只精英；移出视野10只后剩192个身体；空局隐藏；复用不增长。
- 独立复查未发现阻塞问题。
- 修复前后各4次浏览器采样：万剑归宗＋无我剑境、天地一剑＋四象剑阵，每组合重复2次。修复前200只普通敌人仅160显示，修复后200全部显示。
- 修复后极限夹具：202个精英身体＋202个光圈，共404槽。
- 4次暂停均冻结tick与HP，恢复后继续；重开逻辑对象/技能缓存归零，下一次渲染同步后敌人显示归零；最终重新加载普通大厅。无浏览器脚本错误。

## 性能证据边界

Apple M4桌面Chrome，390×844视口，音效及震动关闭。每次预热1.8秒、采样8.5秒；修复后rAF间隔P95约9.2ms。rAF间隔不是60Hz逻辑步率，也不能代表手机性能。不能用修复前少画40只敌人的速度证明性能优越。

夹具使用静止高血量敌人、无敌玩家，并抑制正常生成与拾取；这是显示容量与短时稳定性检查，不是自然通关、长期内存或完整战斗压力验收。极限精英测试后保留404槽属于缓存策略，不是未清理活跃敌人。
