**M0 设计就绪**：7类文档完整、规则冲突已写明处理、每个需求映射验收。不要求虚构角色会签；报告实际审查者与发现。

**M2 剑修切片**：可启动、飞剑与至少一个新功法、选卡、破境、伤害/恢复和退出可操作；展示经审阅的主角样片。未完成全内容时入口标注“开发试玩”。

**M3 完整本期**：六功法、七心法、三丹药、精英/兽王/凝婴/归府、局外/教学全部完成；600局对比、浏览器和微信真机完成；所有已知问题分级。

**M4 发布准备**：政策、素材许可、隐私、包体与实际提审流程另行核实；M3通过不等于已发布。

## 4. 验证与回滚纪律

- 旧报告仅为参考。当前源码、生成副本、构建、模拟报告各记录生成时间和规则版本。
- 先 `npm run cocos:sync`，再 `npm test` 和 `npm run check`；仅在测试完成后构建。新增基础模块被生产入口导入前不假称已同步进包。
- 平衡对照先保存当前源码参数；新规则使用独立显式入口。回滚默认入口即可恢复旧玩法，不能清空存档或覆盖用户未提交修改。
- 不为得到绿灯而随意重写golden；仅在规则变化明确且人工检查后更新，并记录原因。
- 自动化通过不等于美术合格或手机体验合格。没有设备证据的项目保持待验。

## 5. 风险与降级顺序

1. 多重成长导致难度失衡：冻结原对照，逐组启用并做消融。
2. 美术返工：先主角与一种敌人样片；不要批量生成不一致的角色。
3. HUD太满：御剑术并入飞剑信息；心法移到暂停/升级详情；不增加常驻面板高度。
4. 生命周期/演出重复：战斗权威留在Run；演出只确认令牌，重复回调无效。
5. 范围超出：先延后伤害数字装饰、环境变体、第二职业；不砍暂停恢复、旧档兼容和核心反馈。

## 9. 同角色返修与完整平衡批次（2026-10-26）

用户要求先优化同一角色，再制作方向与动作，并开展完整平衡测试。本轮是切片返修和验证，不是正式发布。

| 工作线 | 本轮交付与边界 | 验证依据 |
|---|---|---|
| 美术/技术美术 | 固定黑发蓝白剑修身份，改善头身比、轮廓和暗地面辨识；再制作方向与动作样片 | 同尺度前后对照、80u实景、方向接触表、步态关键帧；生成成功不等于美术通过 |
| 数值测试 | A经典600局、B修仙600局，各完整重复一遍；不边跑边改数值 | 冻结源码哈希、逐局记录、确定性比较、门槛与失败清单 |
| 战斗测试 | 万剑偏好、主动用药、满局外三组独立补充试验 | 明确策略和样本量，不混入主矩阵，不推断真人胜率 |
| 独立QA | 全测试/检查、御剑与进化、减伤、药效时钟、万剑状态边界 | 新旧回归记录、可复现失败；不把自动化通过当作动画验收 |
| 集成 | 独立检视图像与报告，更新本看板及交接 | 如实区分已完成、未通过、未测；不以旧报告覆盖本轮缺口 |

主矩阵1200个配置，含复跑共2400次执行；另有B留出600局、补充300局，共3300次正式执行。各组单独统计，复跑不增加独立样本量。本轮没有修改正式角色或战斗逻辑。

结果：B主矩阵保守/熟练通关率67.3%/94.0%，留出65.0%/93.7%，仍高于目标；主矩阵3局、留出4局超过12分钟；B主矩阵有1次敌弹丢弃，已定位到发射早于临近到期弹丸回收。A/B重复记录一致，484项测试与check通过。完整结果、缺口与复现见[11本轮交付](11-character-and-full-balance-report.md)。

美术只保留完整站姿作为有效待审材料，正/背/斜方向和步态/施法尝试因身份漂移、关节接缝或残影而拒收；已停止同配方扩量。A01与完整平衡验收均未关闭，不以生成张数或测试通过数替代验收。
