# 剑修固定种子试玩与记录

2026-10-27 · Alpha验证。交付可玩的固定初始条件入口、交互记录、导出和离线重放。**真人样本仍待收集；没有得出人类平衡结论。**

## 入口与本轮目标

打开同目录的 `sword-playtest.html`。先选贯穿或剑阵，点击“载入试玩”，再点击游戏内“出山修行”。
桌面使用WASD/方向键，手机使用原触摸摇杆。攻击自动施放，卡片自由选择；路线仅表示意图，不会注入对应功法。

建议先做一次不计分的操作熟悉，再各完成一局贯穿、剑阵。记录为何没选路线卡、升级是否有感觉、死亡时看到了什么。
遇到故障或主动退出也保留样本，不用重打的好结果替代。切出游戏或操作页面按钮后若游戏暂停，按游戏内继续恢复。
一次体验不用于估算玩家胜率，也不能确定两条路线孰强。

## 冻结的初始条件

- 仅 `ruleset=xianxia&playtest=1&route=line|formation` 启用。
- 两条路线都用 `sword-balance-0`，逻辑视野720×1560，firstRun=true，未传入局外加成及装备。
- 试玩档每次出发都重建为空的内存存储，保留并记录音效/无障碍设置；普通试玩、经典玩法和装备测试路径保持原规则。
- 页面用720:1560比例显示游戏；实际可见尺寸、初始设置和安全区写入记录。微小像素取整不改变逻辑视野。
- 页面每次载入使用独立消息通道，收发均校验同源及iframe身份，忽略旧载入消息。

机器人参照固定为已有weapon-first选卡和spore走位，不挑最佳机器人。贯穿种子0存活330.3秒、13级；剑阵308.7秒、18级。
这两局均自然失败；它们能看见完整模拟状态、逐步反应，不能当作与玩家感知条件相同的对手。
玩家选卡和移动不同后，击杀、经验、卡片和遇敌历史会分岔，固定种子不等于相同全过程。

## 记录与恢复

只有专用试玩启用记录。记录内容包括：

- 固定配置、运行规则源码指纹、独立局号；controller为interactive-unverified，不能冒称已确认真人。
- 实际执行步数与输入，含零步输入；相同输入的连续命令压缩，不损失朝向变化。
- 成功选卡的顺序、完整候选、等级和时间；拒绝的点击不记作选择。
- 初始/末尾状态，约每游戏秒及选卡后的HP、最大HP、位置/朝向、等级、经验、属性与库存采样。
- 有效输出按技能、基础/进化、普通怪/Boss分类；受伤保留来源和实际扣血。多步帧内观察时间不是精确命中时间。
- 主动退出单独标记。进行中、暂停时导出是部分样本，不是通关或自然死亡。

专用键 `xianxia.playtest.v1.latest` 每5游戏秒、选卡及结束时暂存当前局；`.previous`保存上一局。观察笔记按局号归属，重开会清空输入，新旧局不会混用。
它不写入正式角色档、不上传服务器。重开会将旧记录移入“上一局”；最多保留最近两局，重要记录应先导出。
刷新后可用“恢复当前暂存”恢复记录，但不会恢复正在运行的游戏。存储失败会显示提示，仍可导出内存记录。
命令容量或总步数超限时标记不可完整重放，不能静默接受不完整记录。

## 重放验证的范围

```sh
node scripts/survivor/playtest-replay.mjs /导出的记录.json
```

先校验格式、配置、容量和规则源码指纹，再根据原输入与实际步数调用step，按原序选择卡片。
校验初始/末尾的记录字段、完整候选、所选卡片、有效伤害分组和受伤总量。
代码版本不匹配、篡改末尾或候选、非法输入、缺失命令会拒绝。

重放不重现屏幕帧率、音画、暂停的墙钟时长；未宣称逐实体快照、每次特效或每个中间采样都相同。
导出的记录来源仍需标注：自动化浏览器冒烟不是人类玩家样本。
机器人与浏览器均使用相同规则摘要；构建前生成指纹并同步共享源码。后续规则更改必须重新生成参照，不能继续比较旧记录。
