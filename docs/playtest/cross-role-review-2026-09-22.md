# 当前十关联合体验评审

2026-09-22 · v1.5 长地图试玩 · 游戏策划／数值策划／测试／美术交互／玩家视角

## 结论

**可以作为机制原型继续迭代，不能按“十关内容质量已完成”验收。** 主要问题不是地图不够长，而是重复组合、空间不成立、奖励选择偏弱，以及标准通关路线之外仍有物理和恢复漏洞。建议先修资产与状态问题，再重做代表关的内容节奏，暂不继续增加关卡数量或长度。

本轮实际覆盖：292 项 Node 测试；Cocos 内十关主路、X、Y 共30条控制输入回放与55项运行检查；浏览器代表性首屏、跳跃、枝冠、地下、树洞、蚁路、暂停及窄屏商城交互；当前关卡、动作、音效、经济、存档代码交叉检查。标准回放知道路线，不等于十位新玩家完整试玩。音效检查到文件和触发逻辑，未作实际听感验收。真机触控、温升、帧率、留存均未验证。

本轮未修玩法与数值。新增的 `audit` 入口只用于浏览器、使用独立内存存档，不读写正常用户资产；可以定位关卡/区域/段落检查画面。

## 优先问题与验收标准

### P0-01：旧金币存档可能被静默覆盖

- **事实／独立内存复现：** 输入版本1、470金币、已拥有诱饵的记录，在没有有效备份时，`ForestRewards` 因 `coins>300` 拒绝读取，随后构造函数按旧完成关补发并写回。仅完成第一关的测试档变成20金币、道具空数组，并显示保存成功。
- 这不是在真实用户存档上做破坏测试；但此前正常页面出现过470余额，因此不能假设所有旧档都不超过300。
- 所在：`js/microforest/ForestRewards.js:14–24`。
- **建议：** 区分历史余额迁移、损坏数据与新版本；不能用本版总产出上限拒绝合法旧余额。读取失败应保留原始记录、显式恢复或迁移，不立刻写入空档。
- **验收：** 0/300/470历史余额、旧道具、主档损坏+备份、双档损坏、未知未来版本均有测试；任何失败不覆盖唯一原始记录。

### P1-02：没跳上岸时会穿进土层

- **事实／可重复物理夹具：** L04第一处沟，角色放在合法左岸 `(410,90)`，普通跳跃后一直向右。约0.883秒到 `(550.9,77.5)`，已进入地面为90的右岸内部；继续落到约 `(597,-50.8)`，随后才触发救回扣血。
- 问题不是“这次跳跃应该成功”，而是跳跃失败应被岸壁挡住，不能穿进土壤。
- 所在：`MicroForestState.js:98–129`；侧面碰撞只在横向首次跨越身体边界且此前脚底低于台面时拦截，随后下落缺少完整重叠消解。
- **建议：** 用上一帧到当前帧的身体扫掠统一解算侧壁和顶部，避免墙角切入；保留合法从下面穿过薄树枝的规则。
- **验收：** 两个方向、不同起跳距离、下降沿、帧率变化、滑翔结束、浮木携带撞岸均不进入实体土层。

### P1-03：死亡中“重置本段物体”可产生零血活动状态

- **事实／内存复现：** HP1受伤→HP0且death存在→调用暂停页对应的`journey.reset()`→death清空、HP仍为0；下一步可从x65移动到x80.8。
- 所在：`ForestJourney.js:44–50`，`MicroForestView.ts`暂停页的重置按钮。
- **建议：** 死亡期间不能走普通局部重置；统一进入死亡恢复流程，或禁用这项操作直到恢复完成。
- **验收：** 死亡、落水救回、洞口转场中暂停/重置/返回地图/再进入，状态均合法；HP0时不能正常移动。

### P1-04：续玩存档损坏会静默当作新局

- **事实／内存复现：** 保存HP2记录，破坏续玩JSON，再加载：restore=false，但saved=true、HP3、回关首。没有备份或读取错误提示。
- 所在：`ForestContinuation.js:4–10`。
- **建议：** 保留最后一份可验证记录；把“无记录”和“读取失败”分开显示。失败恢复不应该让玩家以为最近苔窝仍保存完好。
- **验收：** 截断JSON、缺字段、配额不足、版本变化、R点被删、地下R恢复都有可说明的结果。

### P1-05：加长主要来自模板重复，缺少递进变化

- **事实：** 连同房间共110个段落实例，38个trail、15个fern、11个weight；trail只轮换三组石头位置。fern/hang/canopy共用同一段蕨柄→高土台→落地结构。菌盖和渡口也大量复用固定参数。
- 所在：`ForestLongCampaign.js:17–68`、`SPECS`。
- **体验影响：** 玩家学会第一次之后，后续主要在重复执行，少有观察新信息和改变方案的理由。
- **建议：** 每关按安全教学→一次变化→组合选择→短收尾组织；保留必要赶路和休息，但删掉无变化的重复石阶。长短由内容决定。
- **验收：** 每段都能说清“相对上一段，新增加了哪个判断”；同一机关不能只换名字和横坐标。

### P1-06：树冠与地下的空间设计没有落到当前地图

- **事实：** canopy仍是地面90→平台240→地面90；第八关多次落回同一地表。L06的长地下空间沿同一高度横向铺开。L10树内、地下入口在先后两个段落，尚不是清楚可见的三路共同选择与汇合。
- **浏览器观察：** 第八关“侧风首试”首屏仍是普通苔地、蕨类与小高台；地下主要是深色背景加根阶，没有明显下潜、腔室、采光井之间的空间变化。
- **建议：** L08做一次真正上行后保持高度的连续枝冠，失败可回低路重爬；L06用垂直剖面组织入口、下降、下层选择和回升；L10先展示分岔的环境线索。
- **验收：** 遮掉文字也能区分地面、树内、地下、树冠，并看懂大致前进方向。

### P1-07：生物内容在新版地图中缺失，文案与实例不一致

- **事实：** 新版只有2只甲虫、9只蚂蚁、2只西瓜虫；蜻蜓、毛毛虫、蜗牛均为0，躲藏点也为0。L05有两个beetle段，但生成器只创建第一只。L08“蜻蜓栖枝”实际放的是西瓜虫。
- **建议：** 恢复生物的关卡职责，而不是为了数量填充：蜻蜓提供有预告的穿行窗口，毛毛虫提供短距离载具，蚁队提供间隙，蜗牛可作安全节奏参照。同步删改没有实体支持的提示。
- **验收：** 关卡名、提示、实体类型、动画和接触规则逐一对应；内容校验能发现“有段落名、无对应生物”。

### P1-08：站立侧风不生效，80金币鞋套价值受损

- **事实／模拟：** 侧风bottom=245，站立平台y=240；判定用脚底`y>bottom`。在有效风期4.2秒站到风区中心，运行1秒，位移与windVX均为0。鞋套只在grounded时减半漂移，而真正处在风区的跳跃阶段不减半。
- 所在：`ForestLongCampaign.js:45`、`MicroForestState.js:89`、`ForestTools.js:6`。
- **建议：** 先统一风作用于身体还是脚底、站立还是空中，再决定鞋套的使用场景；保留无需购买也能读懂的基本预告。
- **验收：** 同一站位比较未装备、装备未使用、使用期间、到期后的位移；预告、粒子与实际风场一致。

### P1-09：多数观察奖励几乎是顺路领取

- **证据：** 已有30路线回放中，L01/05/06/07/08/09的X比主路仅多约1.4秒，L03约0秒。多数Y固定多约5.3秒。不是人类探索时间，但结合宝箱固定放在段尾的位置，能确认空间分岔过弱。
- 所在：`ForestLongCampaign.js`的`reward()`与X/Y段分配，`LongCampaignReplay.js`。
- **建议：** X奖励来自发现线索、选择一条可回归支路；Y来自独特操作挑战，不能全部是相同的短藤+箱子。两路可以共享金币上限，但各自的内容奖励必须值得看。
- **验收：** 不看攻略时能预见奖励或发现线索；到达方式与主路有不同判断；回程安全且不要求再重复完整关卡。

### P1-10：实体有碰撞轮廓，但缺少自然宿主

- **浏览器观察与源码对应：** 地下根阶像悬在空中的短木板；树洞是独立竖在路上的圆拱，与树根宿主脱离；细藤旁的巨干是另外画的一层平面，连接关系不够清楚。
- 所在：`ForestCampaignScenery.ts`的root绘制、`ForestJourneyArt.ts:13–54`；地图没有相应自然连接数据。
- **建议：** 画完整的盘根、土壁、截面或枝根连接，再从轮廓定义行走区。不能用“填到地面”遮盖问题，也不能只保留悬浮碰撞板。
- **验收：** 每个平台都能回答“它是什么、从哪里长出来、为什么能承重”；装饰层和实体层保持清晰。

### P2-11：货币总量闭合，但工具和探索价值尚未平衡

- 十关主路200金币，探索总额100；全部付费商品正好300，功能工具合计180。完全收集可以买齐，有限总量本身可以成立。
- 第三关前仅走主路有40金币，示踪绒球正好40；第五关前主路累计80，若买过示踪只剩40，尚不够60的诱饵。若希望一到新机制就试新工具，需要用探索奖励或明确的取舍引导。
- 示踪6秒只是显示已有风向；观察灯照可选纹理；手记主要是标题列表；装扮只有围巾颜色差异。用户不易感到“这次探索改变了我的旅行”。
- **建议：** 暂不调整所有价格；先验证工具能解决具体可选问题，再给每个收藏一张小插画、一句见闻或营地展示。第二条探索线路不再发金币时，开箱应明确获得了哪件纪念。
- **验收：** 新手能说明购买理由、永久拥有/单次持续/每次尝试次数三者区别；X与Y各自有可展示且去重的收获。

### P2-12：上手、暂停和工具信息仍不完整

- 首次进入主要依赖短暂提示和网页外操作说明。暂停页在568×320首屏只见标题、说明、工具和继续按钮，返回地图与重置藏在下面，滚动暗示弱。
- 商城卡片、购买→装备两步反馈清楚，实测200→160，随后显示“装备道具”；但购买前说明没有同时说清永久拥有、每次尝试2次、持续6秒。工具按钮仅在附近有目标时出现，远处无法查看已装备工具/剩余次数。
- **建议：** 前30秒通过安全场景展示一次移动、落地、可交互提示；帮助可重看。暂停常用动作同屏，其他设置折叠；工具信息放在可展开的行囊，避免再加常驻长提示条。
- **验收：** 不看网页外说明也能开始；新玩家能找回帮助、退出、继续和已装备工具；窄横屏首屏主要动作完整。

### P2-13：角色动作已有覆盖，环境与反馈质量仍偏原型

- **保留：** 跳跃起跳/收腿/顶点/下落/落地、推物迈步/顶住、攀爬、滑翔展开、开箱伸手、受伤、死亡与恢复都有状态实现；不能再笼统说“所有动作没做”。
- **待改善：** 小画面里主角与草叶的明度接近；植物类型、树干和低频色块反复出现，长距离缺少不同光区、湿度和地标。部分对象轮廓可读，但不像一个有因果关系的自然空间。
- **建议：** 优先用轮廓、局部光和动静区分主角/危险/可承重物；建立林地、根洞、湿岸、枝冠四套光色与材质节奏，再做局部装饰。
- **验收：** 568×320、844×390、平板横屏中，主角与落点易识别；缩略图不看关名也能区分主要环境。

### P2-14：声音仅完成基础事件层

- 文件与代码存在10类短音效，奖励复用heal、工具复用rest；没有完整的林风、虫鸣、水流、洞内空间等环境层，也没有地图/区域切换的声音性格。
- `ForestAudio`使用三个会被新事件打断的声道，是否听感突兀需实际聆听后决定；本轮没有把源码检查写成听感通过。
- **建议：** 先补危险预告、动作接触和开箱奖励的辨识，再做低密度环境层；给关闭声音后的视觉预告保留等价信息。
- **验收：** 仅凭声音可分辨受伤、恢复、开箱、落地；同屏触发不吞关键预告；真机耳机/外放各测一次。

### P1-15：现有测试覆盖“会玩的路线”，不能证明内容已验收

- 292项测试、55项浏览器检查均通过，但本轮定向探针仍复现穿岸、零血活动和旧资产覆盖。大量旧短关测试不会验证新布局的动物是否存在、支路是否有意义。
- `LongCampaignReplay`使用已知阶段坐标、已知风周期与精确起跳时序。它证明可达性，不证明可理解性、容错性、平衡或真实首玩时间。
- **建议：** 加入失误矩阵、内容与语义校验、最低/最高帧率及输入释放、存档异常场景；人工盲测单独记录犹豫、重试、走错路和主动探索。
- **验收：** 本轮四类状态/存档复现进入回归；所有关键机关都有成功、失败、反向、离开再返回与退出续玩用例。

## 十关逐关策划结论

| 关卡 | 当前判断 | 保留 | 首要整改 |
|---|---|---|---|
| 01 | FAIL：上手段重复偏多 | 安全跳跃与蕨柄 | 5个trail压成有差异的教学；第一次探索有明显发现感 |
| 02 | WARN：弹射主题成立 | 菌盖与树内旁路 | 6个spore实例不能都同参数；树洞需要自然宿主 |
| 03 | WARN：风周期有学习空间 | 绒毛30秒、间歇风 | 两个相同风井改成不同落点选择；补更清晰的到期预告体验 |
| 04 | FAIL：失败路径存在物理问题 | 承重保持、空置5秒回弹 | 修岸壁；5个桥段递进为不同岸形/载荷/返回选择 |
| 05 | FAIL：描述与生物数量不符 | 轻重石与拦虫 | 第二个甲虫段没有甲虫；石头要对选择产生实际影响 |
| 06 | FAIL：地下变成长横廊 | 重量叶片、地下续玩 | 5组配重重复；重做下潜与回升剖面，消除悬浮根板 |
| 07 | WARN：短渡穿插陆路可保留 | 3段短漂流 | 停靠、上岸与载荷做不同变化，不复刻同一条水槽 |
| 08 | FAIL：树冠主题与工具效用未成立 | 攀爬与高路意图 | 连续高度、有效侧风、真正的蜻蜓段 |
| 09 | WARN：目前生物最丰富 | 蚁群间隙、甲虫、西瓜虫 | 3组同型蚁队变化不足；区分无害/预警/攻击和可乘站状态 |
| 10 | FAIL：更像前面模板串联 | 综合运用与多区域 | 做清晰的三路选择与汇合，给终点一个空间和情绪收束 |

FAIL针对内容验收，不表示该关完全无法通关。

## 五个角色的联合判断

| 视角 | Gate | 结论 |
|---|---|---|
| 游戏策划 | FAIL | 动词足够，空间与选择不足；先改善组合质量 |
| 数值策划 | FAIL | 经济账面闭合，机关实际效用与奖励吸引力未闭合 |
| 测试 | WARN | 已知路线可达，失败/中断/旧档兼容存在高优先问题 |
| 美术与交互 | FAIL | 角色状态覆盖好于场景结构，自然宿主与环境变化不足 |
| 玩家视角 | WARN | 能开始、能跳、能买；为什么探索、工具值不值、何时保存仍不够直观 |

可保留的三点：柔茎承重保持有直观因果；孢子弹射与蒲公英滑翔有动作乐趣基础；地图选关与卡片商城比旧长菜单清楚。它们都有实现与运行证据，但不抵消上述缺陷。

## UI Score（启发式评审，不是用户评分）

- Readable：6/10。主要按钮清楚，小场景主角/危险对比和上下文信息仍弱。
- UX：5/10。基础流程通，暂停层级和工具解释需改。
- Accessibility：未验收。568×320代表画面检查完成，尚无真机触控、色觉/动作辅助与多语言验收；当前仅中文、仅横屏。
- Commercial：5/10，仅指虚拟币商城的价值表达；本项目当前不涉及真实支付验收。
- Retention：不作数据评分。30秒后是否想继续的启发式判断为2/5，依据首关重复障碍与发现反馈不足；不是留存率预测。
- Google Play Risk：不适用，已确定只做微信小游戏。

优先级：P0资产保护；P1物理/死亡状态/续玩恢复与核心内容；P2说明、暂停与视觉反馈；P3细节色彩；P4装饰性动画。不得先用装饰掩盖P0/P1。

## 最小整改顺序
