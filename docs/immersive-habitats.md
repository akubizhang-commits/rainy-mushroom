# 全屏实景寻菌改造

## 已实现

- 搜索场景铺满 Canvas 的整个宽高，面积占比 100%；顶部显示返回、进度与右上侧放大镜图标，底部不放操作按钮。点击进度查看篮子，达标后同一区域提供提交入口。短屏不再因统一页面缩放而在左右留下空白。
- 一张 3:2 生境照片按屏幕高度显示，保留整张环境，左右拖动观察不同位置。相机位置在进入鉴定、查看篮子后保留。
- 初次横向拖动时立即隐藏寻觅提示与提示横条；同一局返回场景或切换放大镜不会重新显示，新局重置。
- 32处目标在普通视野中可见、可直接轻点，未发现时没有热点圆框或名称提示。
- 13种菌物使用项目现有照片的透明抠图。底部接触阴影、原场景纹理回绘与不规则遮挡，将目标放入草、松针、落叶和树木之中。
- 放大镜默认关闭，是可选辅助工具。开启后按住查看与普通视野一致的两倍细节，镜头偏移至手指上方；抬起即隐藏。
- 拖动不触发发现；取消手势、切到后台会清除输入状态。采集或被动物吃掉的目标消失，移出篮子后重新出现。
- 搜索计时、鉴定、失败规则与长期存档保留。

## 素材的实际状态

当前没有 API Key，**没有调用图像 API，也没有生成八张全新的写实场景**。可玩的版本使用既有生境实拍图，并另行校准了照片点位。冷湿混交林和落叶林采用更接近林内视角的既有森林照片，原来的树冠远景和放牧草地不再用于这两个搜索关卡。

既有照片只提供代表性环境氛围。高寒草甸的高山植被与地貌、白桦与橡树等具体林型，仍需要新的专门素材才能达到完整构图目标。不能把本次改造描述为已完成八个生境的全新写实绘制。

新场景构图保存在 `js/data/habitatLayouts.js`；现有照片点位在 `PHOTO_SPOTS`。两套坐标分开管理，避免换图后菌物漂离树干或地面。

运行 `npm run prepare:scene-prompts` 会输出八条完整提示词到 `output/imagegen/habitat-prompts.jsonl`，不产生 API 请求。后续通过已授权的图像 CLI 生成图片后，需逐张复核落点，制作场景卡，复制到 `assets/exploration/natural/scenes/` 和 `cards/`，再更新 `js/data/generatedHabitatScenes.js`。未登记的场景不会请求不存在的图片。

透明菌物来自现有照片的多边形抠图，完整作者与许可记录保存在 `assets/exploration/natural/MANIFEST.json`。其中含 CC BY-NC，仍为内部原型素材，不能因为抠图而视为新取得商业授权。

## 本地查看

```sh
npm run preview
```

浏览器打开 `http://127.0.0.1:8765/scripts/preview.html`。桌面侧栏可切换八个场景和三种手机尺寸，拖动与轻点走实际 `ExplorationGame` 输入链路。微信端仍通过开发者工具编译 `game.js`。

## 验证

测试覆盖八个场景、全部32处点位在320×568、375×667、375×812、430×932上的全屏占比与直接点击可达性，以及拖动、可选放大镜、取消/后台、目标消失与恢复、图片加载时不生成隐形点击目标。浏览器 Canvas 预览用于实拍素材与交互目测，不代替微信真机测试。
