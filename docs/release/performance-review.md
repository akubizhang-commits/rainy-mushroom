# 性能优化记录（2026-09-14）

本轮针对 Cocos 正式入口，处理采集顿挫、重复资源引用与森林绘制成本。

## 修改

- `PinePilot` 的场景内 UI 更新不再依赖每次采集递增的业务 revision。采集计数与通知直接更新，只有页面、蹲姿、放大镜或新手提示状态改变时重建HUD。
- 点击采集、跳跃、打开页面不再重复同步保存画面设置；仅设置内容改变时写入。采集收获仍按原规则及时保存。
- 采集照片节点销毁时释放照片引用，避免HUD长期保留导致缓存无法回收。
- `IndexedGeometry` 按完全相同的Float32位置、法线、颜色共享顶点，保留三角形顺序、颜色接缝与纹理坐标。未简化菌物形状或更改碰撞模型。
- 菌物及覆盖物可见性仅在采集、被吃掉或拨开记录变化时更新。
- 复用水面纹理偏移向量，减少每帧临时对象。
- 阴影贴图从1024降为512，投影距离从34缩短至24，滤波档位降低一级。远处阴影细节减少，模型与游戏规则不变；流畅模式继续关闭实时阴影。

## 测量与验收

`node scripts/benchmark-cocos-meshes.mjs docs/release/cocos-mesh-performance.json` 按实际分块与16位索引分段方式统计12个场景。

- 暖湿针阔混交林：514803 → 261571个静态顶点，减少49.2%。
- 全部场景静态顶点减少约24%～51%；三角形数量不变。
- 249项自动测试通过，含颜色/法线接缝、顶点索引完整性测试。
- TypeScript检查通过；浏览器154项实际场景、行走、采集、鉴别、照片读取检查通过，松林画面可正常显示。
- 网页及微信构建通过，微信主包3.72 MiB。

上述顶点统计不等于手机FPS，未宣称帧率提升百分比。仍需在目标手机上测量帧时间、发热和长时间探索表现。保留了完整存档和采集规则。
