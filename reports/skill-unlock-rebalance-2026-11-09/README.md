## 平衡复跑（`balance/before-after.md`）

命令：`node scripts/verify-skill-school-curve.mjs --school=<qi|qiHeavy|formation|yujian|qinglian> --floors=2,3,4,5,6,7,8,9 --seeds=101,211 --modes=move,half --out=<目录>`，改动前后各跑一次，两侧使用同一份脚本。每层每流派4局。各层入层等级：第2层5级、第3层7级、第4层10级、第5层14级、第6层17级、第7层20级、第8层24级、第9层26级。对照表：`node scripts/skill-unlock-balance-compare.mjs <before> <after> <基线根目录> . balance/before-after.md`。

### 剑气：筑基阶段失去剑破虚空

- 现有 qi 列表把点数先给玄月斩和流云斩，筑基期（第5、6层）点数用完，改动前也没有买剑破虚空。所以第2–6层前后完全相同，这份列表测不出筑基期的变化。
- 为了量化，脚本里新增了补充流派 `qiHeavy`（玄月斩→剑破虚空→一剑开天→双月斩→逐月斩→流云斩），没有改动已有流派。它的结果：
  - 第5层（14级）：剑破虚空3换成双月斩3。Boss用时 123 → 153秒（+24%），通关秒数 493 → 441（−11%），胜局 3 → 2。
  - 第6层（17级）：剑破虚空6换成双月斩6＋逐月斩3。Boss 120 → 154秒（+28%），通关 568 → 467（−18%），受伤 2364 → 1300。
  - 第7层（20级）：剑破虚空9换成双月斩6＋逐月斩6。Boss 123 → 177秒（+44%），通关 +3%。
  - 结论：筑基期偏重招的剑气构筑打 Boss 明显变慢（+24%～+44%），清怪反而快一些，因为双月斩和逐月斩是范围伤害。
- 标准 qi 列表在第7层（20级）把剑破虚空3换成双月斩3：Boss 123 → 157秒（+27%），通关 −1%，受伤 2732 → 1853。

### 剑破虚空×1.5在金丹阶段

- 第8层（24级）剑破虚空只能到6级（改动前到10级），另有一剑开天1级。标准 qi：Boss 132 → 110秒（−17%）；qiHeavy：131 → 143秒（+9%）。
- 第9层（26级）：标准 qi Boss 129 → 136秒（+5.5%）；qiHeavy 160 → 160秒（0%）。
- 全部楼层胜局不变（qiHeavy 第5层除外，见上）。
- 建议：×1.5基本抵消了金丹期等级段开放变晚的影响，没有明显偏强或偏弱，建议保持 ×1.5，本轮没有再调。筑基期打 Boss 变慢来自剑破虚空移出筑基，调高倍数解决不了这个问题。

### 三才剑阵冷却变长对剑阵流派

- 剑阵流派各层购买结果前后相同（第5层起有三才剑阵；周天剑域虽然提前到21级，但点数用完，第7–9层都没有买到）。
- 第5层（14级，三才6级）：通关 388 → 489秒（+26%），受伤 682 → 938，Boss 179 → 190秒（+6.5%）。
- 第6层：通关 +4%，受伤 1732 → 2215，最低血量比例 0.37 → 0.29。
- 第7层：通关 −13.5%（483 → 418），受伤 1820 → 1253。第8层 +1%，第9层 −1%（受伤 2379 → 2758，最低血 0.49 → 0.36）。
- 胜局全部不变。三才冷却变长主要影响筑基初期（第5层），之后两仪剑阵成为主力，影响变小，各层有正有负，在4局样本的波动范围内。

## 浏览器验收（`browser/`）

脚本：`node scripts/verify-skill-unlock-rebalance.cjs`（先 `npm run cocos:build`）。使用真实 web-mobile 构建和 Chrome 无头模式，在 1280×720 和 844×390 两个横屏视口各跑一遍。使用内存存档，没有读写真实存档（结束时校验 localStorage 不变）。

对蚀骨剑意、逐月斩、双月斩、剑破虚空、周天剑域、一剑开天逐个检查：
- 技能行位于新阶段的泳道内（炼气巅峰、筑基初期、筑基中期、金丹初期、金丹初期、金丹中期）。
- 角色比可学等级低1级时，详情显示“需角色N级”（7/11/14/21/21/24），学习被拒绝。
- 达到可学等级后学习成功（1级）。
- 进入演武，对固定木桩实际施放：逐月斩、双月斩、剑破虚空、周天剑域、一剑开天都打出了对应来源的命中；蚀骨剑意在普攻或流云斩命中后给目标挂上破绽。

结果：两个视口12项全部通过，status PASS，页面错误0；每个视口的控制台各有1条资源404。截图：`browser/<技能>-tree-<视口>.png`（技能树位置和详情）与 `browser/<技能>-cast-<视口>.png`（演武施放），明细见 `browser/checks.json`。

施放截图的时机：每次切换场景都会弹出加载界面（`PinePilot.assetLoading`），等该场景的图片载入后才消失。第一版脚本在 `enterTraining()` 之后立即推进模拟，150毫秒后截图，12张施放截图中有7张拍到的是加载／标题画面。现在脚本先进入演武，等加载界面关闭（`assetLoading.blocked` 为 false）后再推进模拟、截图，截图前还会断言加载界面没有遮挡画面。重拍后的12张施放截图都显示演武场、木桩和对应技能的特效与伤害数字，12张图片互不相同。技能树截图同样等加载界面关闭后再拍。
