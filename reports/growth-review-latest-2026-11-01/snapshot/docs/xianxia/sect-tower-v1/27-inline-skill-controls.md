# 同页技能树加减点

2026-10-28，用户要求直接在技能树上加减点、点击技能显示同页介绍。本次改变操作方式，保留永久成长和藏经阁职责。

- 每个技能节点放置圆形图标、左下角等级数字、图标下方名称和真实冷却。藏经阁有独立＋、−区域，塔内技能页只显示居中的＋。名称过长时将冷却括号换行。点击图标或名称选中技能，横屏右侧固定展示说明，竖屏在下方固定展示；不跳转、不打开技能详情遮罩。
- ＋立即提交一次修习，界面显示本级所需技能点和首次经卷费用。下一等级条件不足时禁用，并保留原因和详情查看入口。
- −只在宗门藏经阁立即退一级，返还该级实际投入点数。其他宗门页面和塔内宿主拒绝退点/全洗调用。御剑术、累计清1波得到的剑气斩、累计清3波得到的万剑诀，各自绑定1级不能退为自由点。
- 若减点使相关分支的前置不再满足，退回该分支不再有效的投入；进化尽量保留仍满足条件的最高等级。节点和详情提前展示连退名称、等级和总退款，完成后显示实际结果。
- 经卷永久保留，退款不退经卷妖丹，不重置道悟研习次数。已买经卷重新学习不再收经卷费；技能点总量仍最多36。
- 塔内暂停只允许原合同范围内的加点，不创建−按钮，不展示退款预览或全洗入口；说明提示“退点需回藏经阁”。特殊/高阶技能仍在藏经阁学习。全洗功能仅在藏经阁保留独立确认。
- 加减点和选中技能保留树的横向、纵向滚动位置；说明栏独立滚动，切换技能从新说明顶部开始。名称与加减按钮为兄弟节点，没有可点击父节点，防止操作冒泡误开详情。
- 按首次可学的境界和阶段分为九行：炼气6项、筑基6项、金丹4项，详见[33号阶段分配](33-skill-stage-distribution.md)。保留通层、前置、经卷和点数要求，流派分组及前置连线在同一棵可双轴拖动的树中。
- 加减按钮仅显示符号，不显示点数成本。可见面横屏32／竖屏44逻辑单位，透明点击区72／88逻辑单位；在844×390横屏约21px可见、47.5px可点。样片按钮24px可见、44px可点。费用保留在固定详情栏。
- 常驻心法显示“常驻”；万剑诀显示命中间隔而不是虚构施法冷却；万剑归宗显示剑雨周期，详情另列御剑间隔。御剑术当前真实间隔1秒，用户给出的0.5秒仅是格式示例。

## 事务和存档

`TowerGrowth.decreaseSkillQuote(state,id)` 返回只读预览意义的数据：

```text
{ok, reason, returned, changes:[{id,from,to}], skills, evolutionRanks}
```

失败时不含候选分配。`TowerCampaignStore.act({type:'decreaseSkill',id})` 在事务内部重新计算报价；不接受界面传来的退款额或候选等级。只有存盘成功才发布新状态。只读、陈旧写入和保存失败均不改变投入、余额、书籍和原始记录。

前置在旧存档中原本是首次学习条件；单点退款只沿本次降低的节点追踪依赖，不清除历史存档中无关的有效投入。运行时继续使用全部已学技能，进化替换母功法；本次没有恢复“出战槽”。

## 构建兼容

退款变更集合必须用 `Array.from(changes.values())`。当前Creator构建会把迭代器展开 `[...changes.values()]` 转译为 `[].concat(changes.values())`，导致界面读到一个MapIterator，而不是等级变更数组。源码测试不足以发现该问题，构建后浏览器须检查真实退款名称及等级、禁止 `undefined` / `NaN` 文案。
