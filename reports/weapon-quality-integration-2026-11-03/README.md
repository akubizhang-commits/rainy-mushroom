# 武器品质光效正式接入与角色详情同步

用户验收 `design/weapon-quality-v1-2026-11-03` 后，本轮将四档品质光效接入战斗，并按追加要求同步角色详情页；背包人物展示也复用同一渲染器。角色头发和衣服没有按装备更换，没有技能附魔或品阶染色，没有修改装备数值、战斗规则和存档。

## 行为

- 下品与初始装备无额外光效；中品偶尔掠光；上品贴刃流光与短拖尾；极品双束流光、剑尖汇光和3个光点，拖尾稍长。
- 品质读取现有 `weapon.quality`（1–4）；不是凡器/法器/宝器/灵器 `tier`。细剑银白、宽剑暖金。
- 战斗时间驱动光效，暂停不会推进光与拖尾。换武器、品质、朝向/图集、死亡、清理节点或时间回退清除旧轨迹。
- `TowerMenu` 详情页与背包使用 `TowerCharacterArt`，读取当前配装快照。独立展示时钟不推进战斗、不写存档；关闭界面后在 Cocos 销毁帧释放渲染资源。减少动态效果设置下冻结展示动画。
- 详情页仅加载身体和当前剑图，不加载闲置结印动作图集。身体继续复用已有动作图，未重绘。
- 精确剑型范围仍为已接入的素问剑、镇岳剑。其余武器保留现有程序剑型，但品质光效同样有效。不能将本次解释为所有武器设计图都已接入。

## 实现与检查

新增 `WeaponQualityArt.ts` 管理程序光效；`TowerCharacterArt.ts` 增加人身后拖尾层、剑身前光层；`TowerMenu.ts` 替换静态人物图。原素材哈希不变，无生成费用。

19 项相关测试通过（`targeted.log`）。`test-red.log`、`pause-red.log` 保留失败先行证据，其中发现并修复“暂停多次重绘会裁掉最老轨迹”的边界问题。独立代码审查未发现阻塞项，要求实机检查详情长剑与属性栏重叠，已检查。

真实 Cocos 双横屏的详情页8种剑/品质组合、战斗4档、暂停/品质降低/死亡/存档不变合计26项检查，另包含背包截图与关闭清理。为比较同一剑型，四档通过展示层快照模拟；未绕过正式装备合法性验证。第一次脚本错误地改动了装备数据品质，被游戏合法性检查拒绝，已改成只修改隔离的渲染输入，见前次日志。第一次关闭检查没有等待 Cocos 延迟销毁帧，已改为等待销毁完成。

`held-regression` 为首次接入构建的64姿态＋4组真实移动攻击回归，覆盖左右朝向、结印、飞行与重绑定。最终构建仅再禁用菜单未使用的结印图集加载，战斗默认行为不变。最终源文件匹配见 `source-integrity.json`。

未跑全项目测试；既有 host 大测试文件缺少 `TowerBreakthroughAudio` 注入，无法作为本轮验收，保留 `portrait-red.log` 记录，不将其当成本次新增产品缺陷。该测试文件仅补齐本轮新增 `WeaponQualityArt` 依赖。
