# UI 单点精修 · 2026-10-31

## 检查范围

使用 game-ui-design 的 patterns / sharp_edges / validations，检查当前 Cocos Web 构建的宗门主界面、背包、技能树、战斗 HUD，在隔离浏览器中以 1280×720 和 844×390 截图。战斗截图为暂停状态，背包为初始物品；本次并非全物品、激烈战斗或真机的完整视觉验收。

现有风格为宣纸白、青玉绿、墨色文字与克制的旧金点缀，搭配水墨宗门和写实物品图。适合精修信息层级，不必整体换皮。

## 本次落地：技能详情底部操作区

- 原“＋ 技能 1”混合了动作与当前等级，改为“修习功法”“升至 2 级”“已满级”。当前等级仍保留在顶部标签。
- 固定显示消耗或不可修习原因，滚动长说明时仍可见。
- “−”改为“退点”，扩大横向可点击范围。
- 沿用原有青玉主按钮、灰绿禁用态和面板颜色。
- 底栏由 88 增至 120 设计像素，正文可视高度相应减少 32，仍可独立滚动。这是换取固定条件提示的空间成本。
- 改动局限于 TowerMenu 的技能详情底栏。未改变技能数值、学习条件、存档逻辑和其他三个界面。修改前源文件保存在本目录 TowerMenu.before.ts。

## 后续修正：升级条件不关联通关层数

用户确认精修方向，并指出“首通”会把技能升级与通关层数混淆。已删除升级条件栏与通用技能点不足原因中的首通引导，统一显示“技能点不足 · 需 X 点 / 可用 Y 点”。实际 rankCap / skillRequirement 未设置通关门槛，此次无需修改数值规则。

扩展已有零通关测试，逐项验证所有技能在满足当前境界、资源、技能前置条件时，零通关也能逐级升满；连同技能表现测试共 23 项通过。日志见 realm-only-check.log。修正后截图单独存放 requirements-fix/，先前截图保留作修改记录。
