# 侧步接入独立 QA

日期：2026-10-26。范围：角色表现层接入；不修改 Run、共享生产代码、美术文件或其他代理报告，不运行完整平衡矩阵。

## 初始链路与验收边界

初次读取时，`SurvivorView.update` 先输入、再 `run.advance`，最后调用 BattleArt 同步。旧角色显示由 `_inX/_inY` 判断 moving、由 `run.time` 决定上下浮动、由 `player.dirX` 改水平翻转，所有方向共用一个 `player` 帧。`SurvivorBattleArt.load` 同时加载基本战斗图集与地面；新角色资源应是可降级的附加依赖，不应使旧资源正常时整场无法开始。

v3 的 `walk-model.mjs` 是评审用连续关节模型，不是生产接入证据；v4 的图集存在或导出成功同样不代表动作、锚点或运行时加载正确。

## 独立检查矩阵

| 检查 | 输入/操作 | 必须观察的行为 | 证据层 |
|---|---|---|---|
| 实际位移驱动 | 有方向输入但 player.x/y 不变；反向输入但实际位移方向不同 | 站定不持续走帧；相位来源为实际位移，不以按键/墙钟伪造运动 | 控制器单测、宿主 |
| 帧率与相位 | 相同总时间/距离的匀速直线拆成不同次数；同一位置重复渲染 | 相位一致；重复渲染不额外推进；不将限频步态冒充严格锁脚 | 控制器单测 |
| 停止 | 从任意步态松手，位置不再改变 | 可按设计转 idle/停止姿，但不能漂移角色或靠持续走帧伪造滑步 | 单测、浏览器目视 |
| 暂停与升级 | 行走中进入 paused/levelup；恢复原 run | 当前帧和朝向冻结；恢复不补算冻结期墙钟或位移 | 控制器单测、宿主 |
| 左右 | 水平实际位移向左/右 | 与原画基准朝向对应，翻转只作用表现，锚点不横跳 | 单测、atlas 目视 |
| 纯上下 | 上下直行，dirX=0；左右转上下 | 保留最近侧朝向，不来回翻转；单侧资源不得冒充新正背面素材 | 单测、浏览器目视 |
| run 生命周期 | 重开、换 run、位置初始化、回退重入 | 清旧位置/相位，不把跨 run 坐标差当步行距离 | 控制器单测 |
| 经典隔离 | ruleset=survivor 与 xianxia 同输入 | 经典仍使用原角色路径；新增动作不修改经典逻辑/判定 | 控制器与宿主 |
| 资源失败 | 图集/元数据缺失、尺寸错误、加载异常、加载完成前销毁 | 使用旧角色回退；不阻塞基本战斗图集、不显示空白角色或抛未处理异常 | 加载链路、浏览器 |
| atlas 契约 | 32 个 walk frame + idle，尺寸/矩形/锚点/帧序 | 所有矩形在图集范围内；显示尺寸一致；脚底基线与预期相符 | 文件校验、目视 |
| 不改 Run | 控制器读取冻结对象；有/无表现采样的同 seed 短对局 | 不写逻辑位置、方向、时钟、状态、RNG；短对局摘要及随机状态相同 | 控制器与小规模逻辑对照 |

## 修复前实测结果（双 sprite 版本）

下面结果来自双 sprite 淡化版，保留作修复前基线；不能用于证明后续单 sprite 收步版通过。源码哈希记录在 `independent-test-provenance.json`，当时测试过程中四个相关生产文件哈希未变化。

```sh
node --test tests/survivor-side-walk-independent.test.mjs \
  tests/survivor-side-walk-host-independent.test.mjs \
  tests/survivor-character-motion.test.mjs \
  tests/survivor-character-atlas.test.mjs
```

**26/26 通过，0 失败/跳过，211.834 ms；其中独立新增 13 项，工程已有 13 项。** 日志在 `independent-tests.txt`。这不代表下述视觉拒收项通过。

- 实际位置变化才产生步行相位；仅方向输入而位置不变时不走帧；同 tick 重复渲染不额外推进。
- 斜向速度使用欧氏距离，与相同速度的水平运动一致。最新实现是速度驱动、1.4–2Hz 限频，180u/s 对应 1.7Hz；不是先前的固定 cycleDistance 模型。
- 停止时保持相位，过渡完成后持续 idle；输入 sample 使用冻结对象，控制器不修改输入。
- 暂停/升级冻结帧、朝向及停止混合权重；恢复不会把冻结期时长补算成动作。
- 左右镜像符合左朝向原图；纯上下保留上一次侧朝向；更换 Run 会重置相位和朝向。
- 控制器接入前后，经典/修仙各进行 180 步对照，并穿插暂停与重复表现采样：Run 可序列化状态及引用结构一致，包含位置、时钟、池、背包、事件、诊断与 RNG。
- 执行实际 BattleArt.load/sync/destroy 方法，使用轻量 Cocos 对象替身：图片失败、JSON 失败、元数据异常均回退到可见的旧 player；经典加载不请求新资源，旧位置浮动/翻转公式不变；加载期间销毁不会恢复 ready 或持有新角色资源引用。
- Cocos 对象替身能证明方法接线和引用生命周期，不能证明 WebGL 渲染、真实 assetManager 行为或微信端纹理加载。

最早的控制器版本曾在从未移动的第二次静止采样中把 walkWeight 提高到约 0.833，工程测试捕获后已由工程修正。本轮没有改动生产文件。独立测试开发时修正了自身的循环引用快照、浮点近零判断和缺失 seed 等夹具问题，不将其计作生产缺陷。

## 修复前拒收记录：停步双 sprite 淡入淡出产生鬼影

**P2 / 修复前视觉拒收，已被主线程采纳。** 旧版 `SurvivorBattleArt` 同时渲染固定 walk 帧和独立 idle 帧，并分别使用：

```text
walk alpha = round(baseAlpha × walkWeight)
idle alpha = round(baseAlpha × (1 - walkWeight))
```

两幅姿态具有不同的腿脚和手臂轮廓。这是两个透明 sprite 的叠放，不是关节插值或一幅无重影的中间姿态。

可复现的控制器输入：180u/s 运动 60 tick 后停止。此时 phase≈0.7，对应 walk_22；停止第 4 tick（66.667ms）：

| 观察 | 数值 |
|---|---:|
| walkWeight | 0.4444444444444444 |
| walk sprite alpha | 113/255 |
| idle sprite alpha | 142/255 |
| 两幅不透明重叠区域按普通 source-over 的最终 alpha | 0.7532333717800845 |

因此角色躯干重叠区域约有 25% 背景透出，轮廓不同处则保留两套半透明腿脚。不能因为两层 alpha 数字相加为 255 就认定最终完全不透明。停止过程中的 paused/levelup 会正确冻结权重，同时也会把重影中间态冻结，延长可见时间。

证据：

- `independent-stop-blend.json`：真实控制器输出、源码哈希及透明混合计算。
- `independent-stop-blend.png`：实际 v4 图像按输出 alpha 做普通 source-over 合成，包含原 cell 尺寸和近似 80u 显示；已目视确认停止第 2/4/6 tick 的变淡与叠脚。**这是离线合成证据，不是 Cocos 浏览器截图。**

最小修正方向：一次只显示一个确定姿态，避免两套人体轮廓同时可见。若直接切 idle 的姿态跳变不可接受，应使用专门收步帧/关节收步，而不是将当前 walk 帧与独立 idle 淡化叠放。本 QA 不代改生产实现。工程修正后需重新验证中途暂停/升级，以及任意 walk 相位停止。

## 单 sprite 收步新版复查结果

新契约为 32 个 walk 起点各自对应 4 个独立收步姿势。独立测试已改为 `idle/walk/stop` 状态与单个角色 sprite，不继续依赖旧 `walkWeight` 或双槽。

本次实测覆盖：

1. 遍历全部 32 个起点，完整收步期间始终只有一个角色 sprite；alpha 等于原有基值（普通 255、减闪无敌 153、终局 110 等），不受 stopProgress 衰减。
2. 收步保持起点对应关系，四个姿势可依次到达，最后切独立 idle；不移动 Run 角色位置。
3. 在中间 stop 姿势 pause/levelup，重复渲染保持帧、位置、朝向及 alpha；恢复继续剩余收步。
4. 恢复实际移动立即退出 stop、清零 stopProgress，使用 walk 帧，不继续播放旧收步。
5. 新 atlas 的收步矩形、锚点、完整性及失败回退；经典路径不受影响。

新版落盘后执行上文四个测试文件，**36/36 通过，0 失败/跳过，295.294208 ms；其中独立用例 20 项，工程已有用例 16 项。** 日志为 `independent-single-stop-tests.txt`；`independent-single-stop-provenance.json` 记录执行命令、Node 版本及四个生产文件的执行前后哈希，执行期间均未改变。

- 控制器和实际 BattleArt 方法均遍历全部 32 个 walk 起点，确认四张收步帧按序出现，随后进入 idle；完整过程中只有一个角色 sprite，普通 alpha 恒为 255，显示锚点不漂移。
- 中间收步姿势进入 paused/levelup 后，重复采样保持帧、位置、朝向及 alpha；恢复实际位移立即返回 walk，清零 stopProgress。
- 单独验证普通、减闪无敌、无敌闪烁与死亡状态的 alpha 基值 255/153/89/255/110，不受收步进度二次衰减。
- 新增收步图片、JSON、非法元数据失败场景，连同行走资源失败场景均回退到可见旧角色；经典路径、销毁时异步回调及短对局 Run 不变对照继续通过。
- `independent-single-stop-pixels.json` 记录真实图集像素检查与资源哈希：128 张收步帧均无非透明像素触碰格子边缘；32 组末帧在深绿和白底合成后的可见像素均与独立 idle 一致。该检查不能替代中间姿势解剖与动作流畅度目视验收。

修复前双 sprite 叠放与 alpha 衰减问题，在本次源码版本的单元/宿主替身层已确认消除。旧鬼影图片与 JSON 保留不变；真实 Cocos 渲染是否流畅、是否存在素材自身重影，仍须浏览器验收。
