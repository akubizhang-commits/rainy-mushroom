# 随机阶位妖丹：面额与收益节奏修订

2026-10-28，已接入 `TowerRun`、`TowerCampaign` 与宗门塔界面。“父任务”指已完成和继续维护的集成实现，不表示尚未开发。本次只调整纯模块、测试和数值文档，Run/Campaign API不变。

当前一至七阶的折合值为 **1、6、24、30、36、42、48**。例如三阶一颗向既有 `cores` 增加24，不增加24颗实物。钱包仍为“妖丹（折合一阶）”，界面可简称“妖丹值”；结算分别显示本次各阶颗数、折合值和通层/首通奖励。颗数是获得记录，不是未消费的背包库存。书价、研习价格、解锁门槛和其他货币均不变。

## 当前接口与接入兼容

- `CORE_RANK_VALUES`：冻结数组 `[0,1,6,24,30,36,42,48]`，下标是阶位，0表示不掉落。
- `CORE_DROP_RULES[floor]`：按1…9索引的冻结对象。每行包含 `{floor,minCount,maxCount,minValue,maxValue,normalChance,eliteChance,bossChance,targetValue,chancesByRole}`。
- `chancesByRole.normal/elite/boss`：每项都是长度8的冻结数组，按阶位索引；本层没有的角色/阶位组合为0。采样使用这些数组。
- `normalChance/eliteChance/bossChance`：按本层该角色实体数量加权的**候选概率摘要**，不能当作该角色每只怪的掉率，也不能当作最终条件概率。
- `buildCoreDropPlan(floor, seed)`：floor严格为整数1…9，seed为uint32（含0）；返回冻结普通对象，仅有掉落的 `"wave:localId": rank` 项。不掉落的键不存在。非法参数抛 `RangeError`。

每个真实击杀至多掉一颗，阶位严格等于敌人原型阶位，查询命中后按面额即时加到同一个钱包。未击杀、失败、退出、任意击杀子集不补足整层预算；去重由真实击杀台账保证。

```js
const drops = buildCoreDropPlan(floor, savedLootSeed)
const rank = drops[`${wave}:${localId}`]
if (rank !== undefined) earned.cores += CORE_RANK_VALUES[rank]
```

一层编号来自实际 `FLOOR01.waves[].batches[].unit_ids`。二至九层按 `FLOORS[].waves[].enemy_groups`，Boss组稳定排前、其他组保持编排顺序，再逐波编号 `u1...`。键不含attempt前缀；接入方从已验证实体取得wave/localId。模块只导入 `TowerContent.js`，不导入战斗运行时。

新挑战保存 `loot: {version:1, seed}`，逐个击杀记 `coreRank`（0为未掉）。快照校验重建计划并核对台账；Campaign拒绝同一挑战更换种子/规则或改写已记阶位。原先**没有loot字段**的在途旧挑战继续旧20杀普通奖励及旧精英/Boss规则，下次新挑战采用新版；旧余额和既有结算不重算。Campaign仍为schema3，可选 `lastResult.coreLoot` 明细兼容旧结算。

本次是尚未发布的v1内部面额修订；先前线性v1仅用于临时联调存档，不承诺这些临时快照能在新表下继续通过校验，联调应重开挑战。正式发布后的改表须显式处理版本兼容，不能只更新金样测试。当前九层最大uint32种子的金样已更新；同一当前版本的原seed恢复不会重抽，战斗RNG也不会因查表而推进。

## 为什么替换线性原型

第一原型 `[0,1,2,3,4,5,6,7]` 保持了整层均值，却把原精英/Boss的钱转到普通怪：前三波长期收入是旧规则的2.55–3.85倍，一层第19波就拿到93.8%的重复通关收入，旧值为68.3%。这会明显加速提前退出刷钱和缺钱后的永久成长补款，不能按“平衡不变”验收。

该线性原型明确标记为 **REJECTED / 已拒绝**，失败证据完整保留，已被本修订替代：

- [线性版节奏分析](../reports/tower-loot-inline-2026-10-28/drop-linear-tempo.md) / [原始JSON](../reports/tower-loot-inline-2026-10-28/drop-linear-tempo.json)
- [线性版整层分布](../reports/tower-loot-inline-2026-10-28/drop-linear-distribution.md) / [原始JSON](../reports/tower-loot-inline-2026-10-28/drop-linear-distribution.json)
- [线性版设计稿](../reports/tower-loot-inline-2026-10-28/drop-linear-design.md)

提高单颗面额后，可以用低概率高面额保持旧的每击杀期望，而不改一击杀至多一颗的结构。设旧期望为普通0.05，精英按 `[0,3,5,8,10,12,15,18]`，Boss按 `[0,10,15,20,25,30,35,40]`；初始候选概率为 `旧期望/面额`。实际出现的角色/阶位都小于1。不存在的一阶精英、一/二阶Boss不参与公式或采样。

直接按此基础率做整层条件筛选仍有偏差：第六层前三波约低35.27%。因此用精确的前向概率/后向接受概率计算角色×阶位的条件边际，再做有界离线调整：

```text
logit(候选率) += 0.6 × (logit(旧期望/面额) − logit(当前条件率))
```

最终各层只采用1或2轮调整，角色×阶位模型偏差均小于6.5%。也试过逼近0.5%，但第六/九层的接受率降到千分之一量级，故舍弃；没有把昂贵优化放到运行时。基础方案、过度校准结果、最终选择和精确数值均保留在 [原型记录](../reports/tower-loot-inline-2026-10-28/drop-denomination-prototype.json)。当前候选率硬编码在模块，JSON报告同时列出候选率、模型条件率和实际条件率。

## 预算和物理颗数

旧击杀目标仍为 `[63,65,78,87,90,108,105,110,119]`。一层实际有372普通、5精英、1Boss，旧目标为 `floor(372/20)+5×5+20=63`。旧普通计数器跨局余数会令某一层多1，长期基准使用 `N普通/20` 而非逐次丢弃余数。

价值上下界仍为目标±10%向内取整。数量基准是**校准前旧期望对应的颗数** `E0=Σ旧击杀期望/面额`，下界取 `max(1,floor(E0×0.5),达到价值下界至少所需颗数)`，上界取 `max(下界+2,ceil(E0×1.5))`。这是可变化的实物颗数范围，不强制固定颗数或固定整层值。

## 有界生成、兜底与内存

1. 原始seed与floor做域分离/位混合，初始化私有Mulberry32；0是合法seed。不读时间、全局 `Math.random` 或战斗状态。
2. 将同角色/阶位的实体放到固定顺序的池中；用几何分布一次跳过连续未掉落事件，等价于池内独立Bernoulli。命中的实体不重复；最终按原编排索引排序返回。
3. 只接受颗数和值同时合格的候选，最多128次。接受率模型约13.56%–27.06%，平均约3.70–7.38次；128次全部失败概率最高约 `7.99e−9`（独立均匀模型估计，不是枚举全部seed）。
4. 耗尽后做有界二维背包：各阶可用数量二进制分块，在公布的颗数/价值界内求可达状态，优先选离目标值最近者，再选离E0颗数最近者。不能假设目标值总可达，尤其九层119不可达，兜底取120。
5. 在各阶实体池中局部Fisher–Yates选择指定颗数，恢复原编排顺序。它只预先指定真实击杀的掉落，不是在失败或退出时补账。

所有配方均使用本层真实存在的实体。每次几何循环要么结束，要么索引至少加1；重试次数固定，背包倒序更新不重复使用分块，回溯每步减少颗数。因此任何uint32 seed都有界返回。测试把整数PRNG原语临时变为恒零，强迫每次候选全掉落、耗尽128次，九层仍返回合法结果。最坏随机调用上界不超过 `128×682` 加有限兜底选取；正常路径只为跳过段和命中项取随机数。

每层只缓存最近的一个计划和一个8项兜底配方，至多9份计划/236项掉落键；静态实体及索引表为固定4,770个实体，种子数不会扩大内存。背包临时最大9,028字节，结束后只留配方。兜底不强求原角色概率，但其极小尾部不会出现线性版大规模前移；报告不把它冒充严格无限条件重抽分布。

## 实际种子验证与边界

`node scripts/verify-tower-loot-distribution.mjs --samples=100000` 用当前模块对每层10万个seed、合计90万个计划验证：

- 全部计划颗数/值合格、实体和阶位正确；每层颗数及总值各至少3种，不退化为常数。
- 全部4,770个实体均有命中与未命中；Boss实际命中率约82.6%–86.1%，不是必掉。
- 整层均值相对旧目标最大偏差约2.185%，小于5%验收线；九层旧目标排序保留。
- 1/3/5/10/15/19/20波的实际均值，相对保留普通计数余数的旧长期值，最大绝对偏差约5.330%，小于20%验收线。最大正偏差约2.335%，没有原型中的2倍以上早期增益。
