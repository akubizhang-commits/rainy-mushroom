# 可移动施法与双速度：实施记录

2026-11-01。用户已授权按方案开发。行为实现完成，整体数值平衡仍有待调优事项。

## 已实现

- 普攻和技能共用一个角色动作槽，起手、主动连发、收招期间保持互斥；移动不被施法阻断。
- 每模拟步维护技能资格和等待时间，空闲时选择等待最久者；就绪普攻最多被技能插队一次。
- 11种技能/进阶形态使用统一时间表，连续出手按60Hz累计时刻量化。施法速度缩短角色动作，不改变飞剑速度、剑影留印、法阵逐跳或常驻命中窗口。
- 攻击速度继续控制普攻周期和动作；冷却缩减保持独立的既有规则。普通御剑不新增每批1秒CD，新0.20秒起手替换原0.32秒聚剑等待。
- 目标在起手末段锁定；移动后从实际角色位置出手。万剑末段方向根据真实起点与固定落点计算。
- 周天/无我在起手完成后才激活与显示；独立效果不持续占用角色动作槽。
- 存档保留当前动作、锁向、连发进度和候选等待时间；死亡、换波和胜利取消未完成动作及相关前摇显示。
- 角色动作读取同一模拟时钟；较长起手显示技能名、剩余时间和进度条。技能详情、角色面板显示相应时序/速度。

## 装备边界

`TowerEquipment.armorModifiers()` 的 `castSpeed` 目前仍固定返回0。运行时和面板已读取这个接口，公式为 `基础动作时间 / (1 + 施法速度)`；没有擅自新增词条产出或数值。非零加速的时间表、极端值和量化边界有单测，但无法据此声称“实际掉落的施法加速装备已验收”。攻速沿用当前武器接口。

全量基线使用临时副本，将三个战斗模块替换为修改前归档。其余数据来自共享开发目录，存在其他并行工作；因此失败名称对照仅用于识别新增回归，不代表剩余324项失败已逐一定位，也不能将失败数量减少全部归功于本次改动。

部分旧测试假设技能立即生效，已改为等待真实起手。历史“视觉前版本逐帧比较”不再适合改变时序后的战斗，改为比较同一版本在无观察者与抛错/尝试修改事件的观察者下的完整逐帧状态，继续验证表现层不能改变伤害、RNG和移动。

浏览器曾发现Cocos宽松编译下Map迭代器展开不符合Node行为，已改用 `Array.from(candidates.keys())`，最终构建复验通过。训练场观察到长虹起手期间0.1秒移动22单位，进度条仍显示当前施法；测试使用隔离浏览器存储，不改用户正式存档。

## 数值观察：不等于全游戏平衡通过

输入 FOUND：运行源码、修改前三模块归档、技能形态/装备数据、原方案、实际测试结果。缺失：非零施法速度词条最终产出表、等待时间数值目标、完整自然养成采样。因此这些部分为 **NOT ASSESSED — NO DATA**。

`stationary-comparison.json` 使用60秒、60Hz、10个种子、85距离固定高血木桩、铁剑、零XP、无被动。技能等级配置是实验输入，不是合法养成证明。前后仅替换三个动作相关模块，保持其他当前数据一致。重跑：`node scripts/verify-casting-actions.mjs`。

| 配置（技能10级） | 旧平均DPS | 新平均DPS | 变化 |
|---|---:|---:|---:|
| 剑气斩 | 397.50 | 396.98 | -0.1% |
| 长虹 | 625.44 | 625.44 | 0.0% |
| 两仪 | 638.60 | 638.60 | 0.0% |
| 御剑 | 390.68 | 393.64 | +0.8% |
| 周天 | 302.17 | 302.17 | 0.0% |
| 全主动混合 | 1422.00 | 2641.77 | +85.8% |
| 全主动与进阶混合 | 3568.71 | 4200.17 | +17.7% |

混合配置增长主要来自旧固定顺序饥饿被解除：首个种子下，剑影60秒发动1次→20次，两仪0次→7次；御剑发动更少，但一批容纳更多蓄剑。这是需要关注的实质数值变化，不能只因单招伤害未修改就认定DPS不变。本次未擅自削减伤害。

`combat-smoke/balance-casting.json` 使用真实战斗、正常HP/伤害和只控制移动的机器人，固定入层配置、种子419、品质2请求，第1/5/9层及三路线。第1层路线相同，去重后7局，全部通关。装备/经卷获取未模拟，不是自然养成或人工操作验收。
