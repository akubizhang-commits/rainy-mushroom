# 游戏中加载页闪回修复 · 2026-11-03

## 原因与改动

原通用资源队列将所有新资源都列入加载页阻塞批次。战斗中新怪物、掉落图片首次请求时，会再次打开全屏加载页，主循环随之停止推进并重置输入。

- `TowerAssetQueue.ts`：启动默认进入阻塞批次；加载页退出后改为后台加载。显式场景切换才创建新批次。后台失败不进入该批次；当前场景真正需要已有后台请求时，复用请求并等待，不重复下载。
- `TowerLoadingScreen.ts`：增加显式场景切换入口，完成两帧准备后结束阻塞批次。
- `TowerView.ts`：根据实际场景、宗门页面和塔层变化开启加载；相同场景的暂停、恢复、尺寸重绘不会重新开启。沿用现有技能特效预加载。
- `TowerMonsterArt.ts`：入场时加载本层全部波次和 Boss 对应素材，以及已接入的妖猪、狼动作。
- `TowerStoneArt.ts`：入场时准备小尺寸掉落图标；不创建掉落物、不改变奖励。

存档、战斗计算、付费素材源文件未因本次修复修改。测试浏览器使用 `smoke=1` 内存档。

## 验证

- 新增 `tests/tower-runtime-loading.test.mjs`：先观察原代码失败，再验证修复。与现有加载测试合计 11 项通过。
- `scripts/verify-runtime-loading.cjs`：实际 Web 游戏在 1280×720、844×390 下各注入慢加载和三次失败；逐帧观察没有加载页闪回，战斗时间继续推进，可正常返回宗门。结果见 `browser-verification.json`。
- Web 构建通过。启动、场景切换与失败重试的双尺寸浏览器检查全部通过，结果见 `startup/verification.json`。
- 微信 Creator 编译完成，但 `package-wechat.mjs` 的项目包体预算检查失败：总计 118,797,972 字节（约 113.3 MiB），预算 20 MiB；resources 分包为 115,000,821 字节，超过项目配置的单分包预算。没有新增美术文件，本次未扩展为资源分发改造。不能视为微信打包通过，详见 `wechat-build.log`。
- 全量 `npm test`：1921 项，1515 通过、406 失败，不能声称全量通过。逐项名称见 `full-suite-failures.md`，错误见 `full-tests.log`。
- 在隔离目录撤去本次 `TowerView` 场景接入改动后进行对照：405 项同名失败仍存在；另外两边分别出现武器模块缺少导出、CLI 临时结果文件缺失。此对照不等于完整历史基线，未改动这些无关模块。

本报告的验证范围是代码、构建及浏览器实际游戏；微信真机仍需设备验收。
